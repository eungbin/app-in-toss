## 0. 상수·용어

### 0-1. 법령 상수 (값 · 조문 · 출처)

| 키 | 값 | 조문 | 비고 |
|---|---|---|---|
| `BASE_PERIOD_MONTHS` | 18 | 고용보험법 제40조② | 기준기간. 예외는 O-3 |
| `INSURED_DAYS_MIN` | 180 | 법 제40조①1 | 피보험 단위기간 |
| `WAITING_DAYS` | 7 | 법 제49조① | 대기기간. **일수를 줄이지 않는다** |
| `RATE_NORMAL` | 0.60 | 법 제46조①1 | 기초일액 × 60% |
| `RATE_MIN` | 0.80 | 법 제46조①2 | 최저기초일액 × 80% |
| `BASE_DAILY_CAP` | 113,500 | 시행령 제68조① <개정 2025. 12. 23.> | 기초일액 상한 |
| `EARLY_REMAIN_RATIO` | 1/2 | 시행령 제84조① | 잔여 소정급여일수 요건 |
| `EARLY_AFTER_DAYS` | 14 | 시행령 제84조① | 실업 신고일 경과 요건 |
| `EARLY_EMPLOY_MONTHS` | 12 | 시행령 제84조①1 | 계속 고용 요건(65세 이상 6) |

| `STD_WEEK_DIV` / `STD_MONTH_DIV` / `STD_4WEEK_DIV` | 48 / 209 / 28 | 시행규칙 제91조의2 | 1일 소정근로시간 산식 |
| `STD_DAY_HOURS` | 8 | 시행규칙 제91조의2 | 위 산식의 곱 |

**파생값(상수로 넣지 않고 계산한다)**: 일액 상한 = 113,500 × 0.60 = **68,100원**. 8시간 기준 최저기초일액 = 8 × 10,320 = **82,560원**, 최저구직급여일액 = **66,048원**.

### 0-2. 용어
- **기초일액** — 급여의 기초가 되는 임금일액(법 제45조). 평균임금에서 출발해 통상임금 보정 → 상한 → 최저기초일액 순으로 조정된다.
- **최저기초일액** — 이직 전 1일 소정근로시간 × 이직일 당시 최저임금(법 제45조④).
- **최저구직급여일액** — 최저기초일액 × 80%(법 제46조①2).
- **소정급여일수** — 받을 수 있는 날수(별표 1). 대기기간이 끝난 다음 날부터 계산한다.
- **미지급일수** — 재취업일 전날 기준으로 남은 소정급여일수.

### 0-3. 이 앱의 성격을 규정하는 계산 사실 — 화면 설계의 근거

8시간 근로자 기준으로 **일액이 실제로 변하는 구간은 기초일액 110,080원 초과 ~ 113,500원, 월급으로 약 337.6만 ~ 348.1만 원뿐이다.**

| 기초일액 | 일액 | 왜 |
|---|---|---|
| 110,080원 이하 | **66,048원** (고정) | 60%가 최저구직급여일액보다 낮아 법 제46조②로 하한이 적용된다 |
| 110,080 초과 ~ 113,500 | 66,048 ~ 68,100 | 이 구간만 60%가 그대로 작동한다 |
| 113,500원 초과 | **68,100원** (고정) | 시행령 제68조 상한 |

- 따라서 **금액을 훅으로 쓰면 안 된다.** 대부분의 사용자에게 일액은 같은 값이고 변수는 소정급여일수(120~270일)다 ([PRD 1-3](PRD.md)).
- 그리고 **"월급이 다른데 왜 금액이 같나"는 반드시 화면에서 설명해야 한다** (UI-2 AC-6). 설명이 없으면 계산이 틀린 것처럼 보인다.
- 단시간 근로자는 하한 자체가 낮다 — 주 20시간이면 1일 소정 4시간 → 최저구직급여일액 33,024원. **소정근로시간 입력이 필수인 이유다.**

## 1. 데이터 모델

```ts
/** 이직 사유 3갈래 (PRD 0) */
export type QuitReason = 'involuntary' | 'voluntary' | 'voluntaryJustified';

/** 피보험기간 구간 — 별표 1의 5구간 */
export type InsuredBand = 'lt1' | 'y1to3' | 'y3to5' | 'y5to10' | 'gte10';

/** 소정근로시간을 정한 단위 (시행규칙 제91조의2) */
export type StdHoursBasis =
  | { kind: 'day'; hours: number }
  | { kind: 'week'; hours: number; paidHolidayHours: number }
  | { kind: 'month'; hours: number; paidHolidayHours: number }
  | { kind: 'varies4w'; hours4w: number; paidHolidayHours4w: number };

export interface Input {
  reason: QuitReason;
  /** 별표 2에서 고른 항목 번호. reason === 'voluntaryJustified' 일 때만 */
  justifiedItem?: number;
  /** 이직일 현재 만 나이. 50세 경계만 쓴다 */
  ageAtQuit: number;
  /** 장애인고용촉진법 제2조1호 장애인 — 별표 1 비고로 50세 이상으로 본다 */
  disabled: boolean;
  /** 입사일 (ISO). 재직 기간에서 피보험기간·단위기간을 추정한다 */
  hiredDate: string;
  stdHours: StdHoursBasis;
  /** 이직일 (ISO). 3개월 총일수와 최저임금 연도를 여기서 뽑는다 */
  quitDate: string;
  /** 최근 3개월 임금 총액(원) */
  wageTotal3m: number;
  /** 1일 통상임금(원). 모르면 생략 — 법 제45조② 보정용 */
  ordinaryDaily?: number;
}

export type Verdict = 'likely' | 'check' | 'unlikely';

export interface Breakdown {
  verdict: Verdict;
  /** 재직 기간에서 파생 — 사용자가 직접 넣지 않는다 */
  insuredBand: InsuredBand;
  insuredDaysEstimated: number;
  treatedAs50plus: boolean;   // ageAtQuit >= 50 || disabled
  /** 판정 근거 키. i18n 키로 쓴다 */
  reasons: string[];
  periodDays: number;        // 3개월 총일수 (89~92)
  averageDaily: number;      // 평균임금
  stdDayHours: number;       // 1일 평균 소정근로시간
  minBaseDaily: number;      // 최저기초일액
  baseDaily: number;         // 기초일액 (보정·상한·하한 적용 후)
  /** 어떤 조정이 걸렸는지 — 화면 설명 문구를 고르는 근거 */
  applied: Array<'ordinary' | 'cap' | 'minBase' | 'minDaily'>;
  benefitDaily: number;      // 구직급여일액 (원 단위)
  benefitDays: number;       // 소정급여일수
  total: number;             // 일액 × 일수
}

export interface EarlyBonus {
  eligible: boolean;
  /** 미지급일수 */
  remainingDays: number;
  amount: number;
  /** 왜 안 되는지 */
  blockedBy?: 'within14days' | 'remainLessThanHalf';
}

export interface CurvePoint {
  day: number;      // 수급 시작 후 n일째 재취업
  paid: number;     // 그때까지 받은 구직급여
  bonus: number;    // 조기재취업수당
  total: number;
}
```

**저장 스키마** — `createStore('jb')`, 키는 `v1:saved`(계산 결과 최대 3개), `v1:unlockedUntil`(ms), `v1:anonKey`. 스키마 버전 필드 필수.
**이벤트 로그** — `verdict`, `insuredBand`, `benefitDays` 만. **금액·이직 사유는 어떤 형태로도 넣지 않는다** ([PRD 2-3](PRD.md)).

## 3. 기능별 동작 + 인수 조건(AC)

엔진은 전부 순수 함수다. `src/engine/`.

### 3-1. `stdDayHours(basis): number` — 시행규칙 제91조의2

| AC | 입력 | 기대 |
|---|---|---|
| AC-1 | `{kind:'day', hours:6}` | **6** |
| AC-2 | `{kind:'week', hours:40, paidHolidayHours:8}` | (40+8) ÷ 48 × 8 = **8** |
| AC-3 | `{kind:'week', hours:20, paidHolidayHours:4}` | (20+4) ÷ 48 × 8 = **4** |
| AC-4 | `{kind:'week', hours:15, paidHolidayHours:3}` | (15+3) ÷ 48 × 8 = **3** |
| AC-5 | `{kind:'month', hours:174, paidHolidayHours:35}` | (174+35) ÷ 209 × 8 = **8** |
| AC-6 | `{kind:'varies4w', hours4w:160, paidHolidayHours4w:32}` | (160+32) ÷ 28 = **6.857142…** (반올림하지 않는다) |

### 3-2. `averageDaily(wageTotal3m, periodDays): number` — 근로기준법 제2조①6

| AC | 입력 | 기대 |
|---|---|---|
| AC-1 | 9,000,000원 / 92일 | **97,826.0869…** (소수 유지. 절사는 최종 일액에서만 — O-1) |
| AC-2 | 9,000,000원 / 91일 | **98,901.0989…** |
| AC-3 | `periodDays` 가 0 이하 | throw |

`periodDays` 는 이직일 직전 3개월의 달력 일수 합이다(이직일 제외). 산정 기간의 정확한 경계는 **O-2**.

### 3-3. `baseDaily(...)` — 법 제45조, 조문 순서대로 나눠 계산한다

**하나의 산식으로 압축하지 않는다** (work-journal 부동소수 사례). 순서: 평균임금 → ② 통상임금 보정 → ⑤ 상한 → ④ 최저기초일액.

| AC | 상황 | 기대 |
|---|---|---|
| AC-1 | 평균 97,826.09 / 최저기초 82,560 | 원 단위로 버려 **97,826**, `applied` 없음 |
| AC-1b | 평균 110,873.37 | **110,873** → 일액 66,523 (평균을 먼저 버린다. 소수를 유지하면 66,524 로 어긋난다) |
| AC-2 | 평균 130,434.78 | 상한 걸림 → **113,500**, `applied: ['cap']` |
| AC-3 | 평균 39,130.43 / 1일 4시간(최저기초 41,280) | **41,280**, `applied: ['minBase']` |
| AC-4 | 평균 97,826.09 / 통상 111,000 | 통상 보정 → **111,000**, `applied: ['ordinary']` |
| AC-5 | 통상 120,000 | 보정 후 상한 → **113,500**, `applied: ['ordinary','cap']` |

### 3-4. `benefitDaily(...)` — 법 제46조

| AC | 상황 | 기대 |
|---|---|---|
| AC-1 | 기초 97,826.09, 8시간 | 60% = 58,695.65 < 66,048 → **66,048**, `applied` 에 `minDaily` |
| AC-2 | 기초 113,500(상한), 8시간 | 60% = **68,100** |
| AC-3 | 기초 = 최저기초 41,280(4시간) | 80% = **33,024** |
| AC-4 | 기초 110,080 정확히, 8시간 | 60% = 66,048 = 하한 → **66,048** (경계) |
| AC-5 | 기초 110,100, 8시간 | 60% = **66,060** (하한 돌파 첫 구간) |
| AC-6 | 기초 112,500, 8시간 | 60% = **67,500** |
| AC-7 | 기초 = 최저기초 30,960(3시간) | 80% = **24,768** |
| AC-8 | 불변식 | 모든 입력에서 `benefitDaily === min(max(baseDaily × 0.6, minBaseDaily × 0.8), 68,100)`. **테스트로만 확인하고 구현은 조문 순서를 따른다** |

### 3-5. `benefitDays(age50plus, insuredBand)` — 별표 1

| AC | 입력 | 기대 |
|---|---|---|
| AC-1 | 50세 미만 × `lt1` / `y1to3` / `y3to5` / `y5to10` / `gte10` | **120 / 150 / 180 / 210 / 240** |
| AC-2 | 50세 이상 × 같은 5구간 | **120 / 180 / 210 / 240 / 270** |
| AC-3 | 장애인(입력에서 `age50plus: true` 로 매핑) 45세 × `gte10` | **270** (별표 1 비고) |

### 3-6. `eligibility(input)` — 법 제40조·제58조

| AC | 입력 | 기대 |
|---|---|---|
| AC-1 | 비자발 + 추정 재직 210일 이상 | **`likely`** |
| AC-2 | 추정 재직 179일 | **`unlikely`**, `reasons: ['insuredShort']` |
| AC-2b | 추정 재직 180~209일 | **`check`**, `reasons: ['insuredNear']` — 달력 일수는 실제 단위기간보다 **크거나 같다**(무급휴직·결근은 세지 않는다). 그래서 위험한 구간은 180 미만이 아니라 **180을 조금 넘긴 구간**이다 |
| AC-3 | 자발 + 정당한 사유 선택 없음 | **`unlikely`**, `reasons: ['voluntaryNotJustified']` |
| AC-4 | 자발 + 별표 2 항목 선택 | **항상 `check`**, `reasons: ['justifiedNeedsProof']` — 단정하지 않는다 ([PRD 2-2](PRD.md)) |
| AC-5 | 비자발 + 180 이상이지만 이직일이 오늘 이후 | `check`, `reasons: ['futureQuitDate']` |

### 3-7. `total(benefitDaily, benefitDays)` · 대기기간

| AC | 상황 | 기대 |
|---|---|---|
| AC-0 | **총액은 버리기 전 일액으로 곱한다** | 일액 66,523.8 · 180일 → **11,974,284**. 표시 일액(66,523) × 180 = 11,974,140 과 다르다 — 관공서 화면값이 이쪽이다 |
| AC-1 | 66,048 × 180 (하한이라 소수 없음) | **11,888,640** |
| AC-2 | 68,100 × 270 (최대) | **18,387,000** |
| AC-3 | 33,024 × 150 | **4,953,600** |
| AC-4 | 24,768 × 120 | **2,972,160** |
| AC-5 | 대기기간 | 총액에서 **차감하지 않는다.** 소정급여일수는 대기기간이 끝난 다음 날부터 계산된다(법 제49조·제50조①). 화면에는 "첫 7일은 지급되지 않아요 — 받는 날수는 그대로예요"로 표기 |

### 3-9. `curve(benefitDaily, benefitDays)` — S03

| AC | 기대 |
|---|---|
| AC-1 | 점의 개수 = `benefitDays + 1` (0일째 ~ 마지막 날) |
| AC-2 | `paid` 는 단조증가, `total` 은 **1/2 경계에서 단조가 아니다** — 그 계단이 이 화면의 핵심이다 |
| AC-3 | 일액 66,048 · 소정 180 일 때 90일째 `total` = 90×66,048 + 2,972,160 = **8,916,480**, 91일째 = 91×66,048 + 0 = **6,010,368** → **감소한다** |
| AC-4 | 잠금 상태에서 `curve()` 를 호출하지 않는다. **뼈대 막대(skeleton)** 만 렌더한다 — 점(`●●●`)은 가짜 숫자나 오류처럼 보인다([net-pay SCREEN_FLOW 6-3](../../net-pay/docs/SCREEN_FLOW.md)) |

## 5. 비기능

- **성능** — 초기 렌더 2초 이내. 데이터 JSON 합계 100KB 미만. 곡선은 최대 271점이므로 캔버스 1회 렌더로 충분하다.
- **접근성** — 잠금 수치는 DOM 에 넣지 않는다(흐림만으로는 접근성 트리에 남는다). 잠금 표시는 뼈대 막대. 배지는 색만으로 구분하지 않고 문구를 함께 둔다.
- **문구 린트** — 금지어 3그룹([PRD 2-2](PRD.md)). 화이트리스트에 "고용보험법"·"고용보험 가입기간"(법령·제도 명칭)을 넣어 오탐을 막는다.
- **오프라인** — 광고 SDK 외 런타임 외부 호출 0. 네트워크가 없어도 계산은 전부 동작한다.
- **i18n** — `ko.json` 하나. 카피는 화면 흐름 문서의 카피 일람이 원본이다.
