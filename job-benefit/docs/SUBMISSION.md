### 1-2. 상세 설명 (콘솔 "상세 설명")

**"접속 → 행동 → 결과" 흐름으로 쓴다.** "무엇이 아니다" 로 지면을 채우면 반려된다(rent-calc 사례).
심사 진술은 마지막 단락에 몰아 둔다.

> 실업급여 되나요?는 구직급여의 수급 요건과 예상 지급액을 계산하는 서비스입니다. 앱에 들어가면 이직 사유, 입사일과 퇴사일, 만 나이, 일주일 근로시간, 최근 3개월 월급을 넣는 화면이 나옵니다. 값을 넣고 결과 보기를 누르면 고용보험법의 요건을 충족하는지, 하루 얼마를 며칠 동안 받게 되는지, 전체 예상 금액이 순서대로 나옵니다. 스스로 그만둔 경우에는 시행규칙 별표 2의 정당한 이직 사유 목록을 확인할 수 있고, 재취업 시점을 바꿔 가며 조기재취업수당을 포함한 총액이 어떻게 달라지는지도 볼 수 있습니다. 계산 결과는 입력값과 법령 수치에 따른 예상 금액으로, 실제 수급 자격과 금액은 고용센터의 판단에 따라 달라질 수 있습니다. 고용보험이나 고용노동부가 제공하거나 인증한 서비스가 아니며 신청·접수 기능은 없습니다. 입력한 값은 기기 안에서만 계산되고 외부로 전송되지 않습니다.

**글자 수를 등록 직전에 실측한다** — 위 문단은 공백 포함 **440자**다(제한 500자).

## 2. 채널톡 서비스 설명 (앱 정보 검토에서 요청이 오면 바로 보낸다)

rent-calc 가 "앱 정보만으로는 서비스 확인이 어렵다" 로 반려됐다. 그때 왕복을 한 번 줄이려고 미리 적어 둔다.

> **핵심 기능 1 — 수급 요건 판정**
> 넣는 값: 이직 사유(회사 사정/본인 사정/본인 사정이지만 정당한 사유), 입사일·퇴사일, 만 나이, 주 소정근로시간, 최근 3개월 월급.
> 나오는 결과: "요건을 충족하는 것으로 보여요 / 확인이 필요해요 / 요건에 미치지 않아요" 중 하나. 단정하지 않습니다. 정당한 사유를 고른 경우에는 증빙과 인정 여부를 고용센터가 판단하므로 **항상 "확인이 필요해요"** 로 냅니다.
> 근거: 고용보험법 제40조(기준기간 18개월·피보험 단위기간 180일), 제58조(수급자격 제한), 시행규칙 별표 2(정당한 이직 사유 14개 항목).
>
> **핵심 기능 2 — 예상 지급액 계산**
> 예시: 2023-03-01 입사, 2026-09-01 퇴사, 만 45세, 주 40시간(주휴 8시간), 월 300만 원 → 하루 66,048원, 180일, 모두 받으면 11,888,640원.
> 근거: 기초일액은 평균임금(근로기준법 제2조제1항제6호), 상한 113,500원(시행령 제68조), 하한은 이직 전 1일 소정근로시간 × 최저임금(법 제45조제4항). 일액은 기초일액의 60%, 최저기초일액이 적용되면 80%(법 제46조). 소정급여일수는 연령·피보험기간에 따라 120~270일(별표 1).
> 위 예시는 고용보험 구직급여액 모의계산 결과와 대조해 값이 일치하는 것을 확인했습니다(2026-09-11).
>
> **수익 모델**: 인앱 광고(보상형 1종, 배너 1종)뿐입니다. 결제·구독은 없습니다. 보상형 광고는 재취업 시점별 총액 화면을 하루 동안 여는 용도로만 쓰고, 포인트나 현금성 보상은 지급하지 않습니다.
>
> **하지 않는 것**: 실업급여 신청·접수·대행을 하지 않습니다. 고용보험·고용노동부가 제공하거나 인증한 서비스가 아닙니다. 금융 상품을 노출하거나 권유하지 않습니다. 입력값은 기기 안에서만 계산하며 서버로 전송하지 않습니다(서버가 없습니다).

### 3-3. 남은 작업 (의존 순서)

1. **콘솔에 앱 등록** — 1-1 표 입력. 카테고리 소분류를 여기서 확정한다
2. **광고 그룹 2개 생성**(리워드·배너) → ID 를 `.env` 에. 정산 정보 검토 통과 후에만 메뉴가 열리고 구글 등록까지 최대 2시간
3. **배포 키 발급**(콘솔 → 워크스페이스 → 키) → `npx ait token add job-benefit`. 키는 **앱 범위**라 다른 앱 키로는 4031 이 난다
4. `npm run build` → QR 테스트(3-2) — 테스트 광고 ID 로
5. 스크린샷 5장 등록(이미 만들어 둠) + 앱 정보 검토 요청
6. `.env` 를 실 광고 ID 로 → `npm run build:release` → `npm run deploy:release`
7. 번들 검토 요청 → 승인 → 출시

**앱 정보 심사와 번들 심사는 별개다.** 앱 정보가 승인돼도 번들은 버전 목록에서 따로 검토를 요청해야 한다.
