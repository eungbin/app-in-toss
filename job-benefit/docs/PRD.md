## 1. 서비스 정의

### 1-1. 한 줄 정의
퇴사를 앞두었거나 이미 퇴사한 사람이 **"나 실업급여 받을 수 있나, 얼마를, 며칠 동안"** 을 한 화면에서 확인하는 계산기.

### 1-2. 무엇이 아닌가 (심사 대응의 출발점)
- **고용보험·고용노동부가 제공하거나 인증한 서비스가 아니다.** 신청·접수 기능이 없고 어떤 값도 기관에 전송하지 않는다.
- **수급 자격의 최종 판정이 아니다.** 자격은 직업안정기관의 장이 인정한다(법 제40조·제58조). 이 앱은 법령 수치에 따른 **참고 판정**만 한다.
- **금융 상품이 아니다.** 대출·보험·카드 어떤 상품도 노출·추천·링크하지 않는다.
- **퇴사를 권하는 서비스가 아니다.** "지금 그만두면 이득" 류 문구를 금지어로 막는다.

### 1-3. 왜 이 조합인가
- 공식 모의계산기는 **금액만** 알려 준다. 사용자가 막히는 지점은 "내가 대상인가"다 → 판정을 앞에 둔다.
- 상·하한 차이가 2,052원뿐이라([DATA_VERIFICATION 4장](DATA_VERIFICATION.md)) **일액은 사실상 정액에 가깝다.** 금액을 훅으로 삼을 이유가 약하고, 변수는 **일수**(120~270일)에 있다.
- 조기재취업수당(잔여일수 1/2 이상 + 12개월 계속 고용 → 일액 × 미지급일수 × 1/2)은 공식 계산기가 다루지 않는다 → 차별점 B.

### 1-4. 타깃 사용자
- 퇴사를 앞둔 직장인, 계약 만료·권고사직을 통보받은 사람, 이미 퇴사하고 신청 전인 사람.
- **알바·단시간 근로자**가 실제로 많이 걸린다 — 하한이 1일 소정근로시간에 비례하기 때문(법 제45조④). work-journal 사용자층과 같다.

### 1-5. 성공 지표 (출시 후 90일)
| 지표 | 목표 | 근거 |
|---|---|---|
| 세션당 판정 완료율 | 60% 이상 | 입력이 5개를 넘으면 이탈한다 |
| 리워드 광고 시청률(게이트 도달자 기준) | 25% 이상 | net-pay·rent-calc 수준 |
| 공유 카드 생성률 | 5% 이상 | 무료·금액 숨김 토글 제공 |
| 재방문 | **KPI로 잡지 않는다** | 1회 쓰고 끝나는 도구 앱이다(photo-standard 복구에서 배운 것) |

## 2. 심사 대응 원칙 (설계 제약)

### 2-1. 원칙 A — 금융 상품과의 거리
실업급여를 담보로 한 대출·생활비 대출·보험 어떤 상품도 노출·추천·링크하지 않는다. 카테고리에서 `재테크`를 고르지 않는다.

### 2-2. 원칙 B — 자문이 아닌 참고 계산
- 결과를 **"받을 수 있어요"로 단정하지 않는다.** 세 가지 상태만 쓴다: **요건을 충족하는 것으로 보여요 / 확인이 필요해요 / 요건에 미치지 않아요**.
- 자발적 이직에서 정당한 사유를 고른 경우는 **항상 "확인이 필요해요"** 다. 증빙과 인정 여부는 기관이 판단한다.
- 모든 결과 화면에 기준일(법령 시행일·최저임금 연도)과 면책을 넣는다.
- 금지어 3그룹: ① 상품(대출·보험·카드·투자) ② 권고(그만두세요·이득·유리해요·추천) ③ 오인(공식·제공·인증·신청·접수·대행).

### 2-3. 원칙 C — 개인정보 최소화
임금·이직 사유는 기기 안에서만 계산한다. 이벤트 로그에 **금액을 어떤 형태로도 넣지 않는다.** 이직 사유 선택값도 로그에 넣지 않는다(민감정보에 가깝다). 화면에 한 줄: "입력한 값은 이 기기 안에서만 계산돼요."

### 2-4. 원칙 D — 광고 보상은 기능 잠금 해제만
보상 = "오늘 하루(기기 로컬 자정까지) 재취업 시점별 곡선 열기". 포인트·현금성 보상 없음. `userEarnedReward`에서만 지급하고 `dismissed`로는 지급하지 않는다.

### 2-5. 콘솔 상세 설명 문구 (초안, 500자 이내 · "접속 → 행동 → 결과" 흐름)
> 실업급여 되나요?는 구직급여 수급 요건과 예상 지급액을 계산하는 서비스입니다. 앱에 들어가면 이직 사유, 나이, 고용보험 가입기간, 1주 소정근로시간, 최근 3개월 월급을 입력하는 화면이 나옵니다. 값을 넣으면 고용보험법의 요건을 충족하는지, 하루 얼마를 며칠 동안 받게 되는지, 전체 예상 금액이 얼마인지 순서대로 보여 줍니다. 재취업 시점을 바꿔 가며 조기재취업수당을 포함한 총액이 어떻게 달라지는지도 확인할 수 있습니다. 계산 결과는 입력값과 법령 수치에 따른 예상치로, 실제 수급 자격과 금액은 고용센터의 판단에 따라 달라질 수 있습니다. 고용보험이나 고용노동부가 제공하거나 인증한 서비스가 아니며, 신청·접수 기능은 없습니다. 입력한 값은 기기 안에서만 계산되고 외부로 전송되지 않습니다.

(글자 수는 SUBMISSION 작성 시 실측한다.)

## 3. 핵심 사용자 흐름

```
홈(판정 입력) ─▶ 결과(판정 배지 + 일액 + 일수 + 총액)
                   ├─ [정당한 이직 사유 보기] ─▶ 시트(별표 2, 13항목)
                   ├─ [공유 카드] ──────────── 무료, 금액 숨김 토글
                   └─ [재취업하면 얼마 남을까] ─ 게이트 ─▶ 시점별 총액 곡선
```

### 3-1. 첫 화면 = 판정 입력 (핵심)
입력 5개. 진입 즉시 바텀시트를 열지 않고, 입력창 자동 포커스도 하지 않는다.
1. 이직 사유 3갈래 (세 번째를 고르면 별표 2 시트로 안내)
2. 이직일 현재 나이 (50세 기준만 쓰므로 "만 50세 이상" 토글로도 충분 — 화면 흐름에서 결정)
3. 고용보험 가입기간 (피보험기간, 5구간 선택)
4. 1주 소정근로시간 + 주 유급휴일 시간 (하한 계산용)
5. 최근 3개월 월급

### 3-2. 결과 = 판정 배지가 맨 위
배지(3상태) → 일액 → 소정급여일수 → 총액 → 대기기간 7일 안내 → 기준일·면책. 금액보다 **일수**를 크게 보여 준다(1-3).

### 3-3. 재취업 시점별 곡선 (차별점 B, 게이트)
가로축 = 재취업 시점(수급 시작 후 n일), 세로축 = 그때까지 받은 구직급여 + 조기재취업수당. **1/2 지점에서 계단이 생기는 것**이 이 화면의 전부다 — 그 지점을 넘기면 조기재취업수당이 사라진다.

### 3-4. 공유 카드 (무료)
판정 결과 요약. 금액 숨김 토글(기본 켜짐 — 남에게 보내는 카드에 내 임금이 들어가지 않게). 카드 하단에 딥링크.

## 4. 기능 요구사항

우선순위: **P0 = 출시 필수**, P1 = 출시 후 4주 내, P2 = 검증 후.

### 4-1. 계산 엔진 (P0) — 순수 함수, 단위 테스트

| ID | 요구사항 |

| CE-2 | `avgWage(months[3]) → number`. 근로기준법 제2조①6 — 3개월 임금 총액 ÷ 그 기간 총일수. **총일수는 실제 달력 일수**(89~92일). net-pay 퇴직금 로직과 같은 정의. |
| CE-3 | `dailyStdHours(input) → number`. 시행규칙 제91조의2 — 일 단위는 그대로 / 주 단위는 (주 소정근로시간 + 유급휴일 시간) ÷ 48 × 8 / 월 단위는 ÷ 209 × 8 / 주마다 다르면 4주 합계 ÷ 28. |

| CE-7 | `total(benefitDaily, benefitDays) → number`. 대기기간 7일은 **지급 시작일을 늦출 뿐 일수를 줄이지 않는다**(법 제49조 — 소정급여일수는 대기기간이 끝난 다음 날부터 계산). 이 구분을 테스트로 고정한다. |
| CE-8 | `earlyBonus(benefitDaily, benefitDays, reemployDay) → { eligible, amount }`. 실업 신고일 +14일 경과 & 재취업 전날 기준 잔여일수 ≥ 소정급여일수 × 1/2 & 12개월 이상 계속 고용 전제 → **일액 × 미지급일수 × 1/2**(시행령 제85조). |
| CE-9 | `curve(benefitDaily, benefitDays) → [{ day, paid, bonus, total }]`. 3-3의 곡선 데이터. 1/2 경계에서 계단이 생기는 것을 테스트로 고정. |
| CE-10 | (P1) 피보험기간 합산(법 제50조④ — 상실 후 3년 이내 재취득 시 합산, 그 상실로 수급한 이력이 있으면 제외). v1.0은 사용자가 합산된 기간을 직접 고른다. |
| CE-11 | 골든 테스트 20건 내외. 기대값은 **원문 숫자 리터럴 산술**로 만들고, 별도로 고용보험 모의계산 결과와 대조해 `FACT_CHECK.md`에 조회 조건·결과·조회일을 표로 남긴다. 경계 케이스 필수: 상한 초과, 최저기초일액 적용, 단시간(주 15시간), 50세 경계, 피보험기간 구간 경계 5곳, 잔여 1/2 경계. |

## 7. 기술 아키텍처
- Vite + React 18 + TS, `@apps-in-toss/web-framework` 3.3.x, vitest. dev 포트 5178.
- `@ait/kit` — 광고·저장·네비·백스택·공유·환경·i18n·익명 사용자. 앱 안에 다시 만들지 않는다.

## 11. 열린 질문
- **Q1. 카테고리 중분류** — `편의 > 도구`가 1순위, 둘째로 `정보`. 소분류는 콘솔에서만 보인다 → **콘솔 등록 단계(13)에서 사용자가 확정.**
- **Q2. 고용보험 모의계산 페이지 경로** — 골든 대조용. **9단계(엔진 + 골든)에서 브라우저로 확인해 기입.**
- **Q3. 나이 입력을 "만 50세 이상" 토글로 줄일지, 생년월일을 받을지** — 계산에 쓰는 것은 50세 경계뿐이다. **화면 흐름(6단계)에서 확정.**

Q1~Q3은 모두 **닫히는 단계가 정해져 있다.** 지금 막히는 것은 없다.
