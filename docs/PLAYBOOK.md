| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (2026-09-08) |
| 용도 | 새 미니앱을 시작할 때 따르는 절차. 세 앱(fx-replay, net-pay, rent-calc)을 만들며 굳어진 순서와 함정을 적었다 |
| 형식 | 단계별 체크리스트 + 기존 문서 링크. 앱별 세부 수치는 여기 두지 않고 각 앱 `docs/`를 가리킨다 |
| 갱신 | 새 앱을 출시할 때마다 "배운 것"(6장)에 한 줄 추가. 절차가 바뀌면 해당 단계만 고친다 |

## 0. 원칙 (모든 앱에 공통)

1. **문서가 코드보다 먼저.** PROJECT_CONTEXT → PRD → 기능 명세 → 화면 흐름이 끝난 뒤 코드를 쓴다. 확정된 결정은 재논의하지 않는다. 확인 결과가 전제를 바꾸면 "재논의"가 아니라 "확인 결과가 전제를 바꿨다"로 근거와 함께 제시한다.
2. **차별점은 하나, 나머지는 표준 수준.** 첫 화면에서 설명 없이 체감되는 훅 하나 + 공유 카드에 쓸 요소 하나. 출시 속도가 우선이다.
3. **v1.0은 광고 전용, 서버 0.** 인앱결제는 토스 로그인 + mTLS 파트너 서버가 필요하므로 v1.1로 미룬다. 데이터는 전부 번들에 정적으로 넣고 런타임 외부 호출은 앱인토스 SDK(광고)만.
4. **비용 0원.** 데이터·인프라·입점 모두 무료. 정산에 필요한 사업자 등록과 팝빌만 예외.
5. **카테고리는 금융을 피한다.** 유틸리티나 라이프·콘텐츠. 재테크·금융은 금융 조항 렌즈로 심사된다. 게임·교육도 피한다(등급분류 비용, 자격 요건).
6. **포트폴리오.** 앱 하나의 광고 수익은 작다. 같은 템플릿으로 여러 개를 만들고 `intoss://` 스킴으로 서로 링크한다.
7. **공용 코드는 `@ait/kit`.** 광고·저장·네비·백스택·공유·환경·i18n·익명 사용자는 앱 안에 다시 만들지 않는다. 설계는 [SHARED_PACKAGE.md](SHARED_PACKAGE.md).
8. **정확성은 원문으로 증명한다.** 계산 결과는 공공 계산기·법령 원문과 대조한 골든 테스트로 고정하고 `FACT_CHECK.md`에 기록한다. 기대값은 구현 코드를 거치지 않는 경로로 만든다.

## 2. 단계별 체크리스트

### 2-1. 아이디어 후보 비교
후보를 3~4개 뽑아 같은 축으로 비교한다. 가이드·안내형 앱은 만들지 않는다(독자가 개발자면 채널이 틀렸다).

| 축 | 통과 기준 |
|---|---|
| 대상 | 토스 일반 사용자(만 19세 이상)가 바로 쓰는 도구. 개발자·전문가 대상 아님 |
| 서버 | 0. 데이터가 불변이거나 갱신이 연 몇 회 이내 |
| 데이터 라이선스 | 상업 이용 가능(법령, 공공누리 1유형, 한국은행 작성 통계, "이용허락범위 제한 없음") |
| 기존 자산 재사용 | `@ait/kit` + 기존 파이프라인(ECOS, 법령 별표 파서, HWPX) 중 재사용 가능한 것 |
| 심사 리스크 | 금융 상품·투자 자문·법률 자문·의료·게임성에서 먼 것 |
| 수요 | 상시 수요 우선. 시즌성이 강하면 광고 수익이 불안정 |
| 차별점 | 한 줄로 말할 수 있는 훅 하나 |

- [ ] 비교표 작성 → 1개 선정, 나머지는 후속 후보로 기록
- [ ] 선정 이유 3줄

### 2-2. PROJECT_CONTEXT
기획 대화의 인계 문서. 구조: 한 줄 정의 / 확정된 핵심 결정(표) / 지켜야 할 제약(심사 정책) / 데이터 전략 / 수익 모델 / 인프라 / 제품 설계 포인트 / 확인 필요(체크박스) / 다음 단계 / 참고.
- [ ] 앱 이름(국문·영문·폴더명) 후보 — 영문 15자 이내 명사형
- [ ] 차별점(메인 훅)과 공유 카드 요소 확정
- [ ] 카테고리 결정과 이유
- [ ] 착수 시점(직전 앱 심사 제출 이후인지)
- [ ] "확인 필요" 항목마다 누가(사용자 결정 / 조사) 닫는지 표시

### 2-3. 데이터·라이선스 검증
- [ ] 소스마다 작성기관·이용 조건·원문 URL·확인일. ECOS는 통계표별 `ORG_NAME` 확인(한국은행 작성만 출처표시로 상업 가능, 타 기관은 승인 필요)
- [ ] 공공데이터포털은 유형 확인(1유형 OK, 2유형 상업 금지). 법령·고시는 저작권 보호 대상 아님(저작권법 제7조)
- [ ] 자동 수집 가능 여부: 국가법령정보센터 **별표는 평문 다운로드 가능**(`lsBylTextDownLoad.do`), **조문 본문은 JS라 불가** → 상수 + 출처 URL. 공공데이터포털 HWPX는 ZIP+XML로 의존성 없이 파싱 가능. 홈택스·손택스·4대보험센터·법령 조문은 브라우저로만 조회
- [ ] 데이터 갱신 주기와 갱신 방법(데이터 교체 → `check:data` → 재제출)
- [ ] 심사 방어용 컷오프가 필요한지(fx-replay는 시세를 12개월 컷오프, 계산기류는 최신값 필수)

### 2-4. PRD
net-pay PRD의 12장 구조를 그대로 쓴다: 0 확정 사항 / 1 서비스 정의(한 줄, 무엇이 아닌가, 왜 이 조합, 타깃, 성공 지표) / 2 심사 대응 원칙 A~D(금융 상품 거리, 자문 아닌 참고, 개인정보 최소화, 광고 보상은 기능 해제만) + 콘솔 설명 문구 초안 / 3 핵심 흐름 / 4 기능 요구사항(CE·DT·UI·MZ·US, P0/P1/P2) / 5 데이터 소스 / 6 수익 / 7 아키텍처 / 8 리스크 매트릭스 / 9 범위 제외 / 10 마일스톤 / 11 열린 질문 / 12 변경 이력.
- [ ] 면책·기준일 문구 확정(B1·B2), 금지어 그룹 초안(B3)
- [ ] 게이트 구성: 메인 훅은 무료, 공유 카드는 무료(유입 수단), 게이트는 "결과를 본 직후 더 알고 싶은 것"
- [ ] 열린 질문을 사용자에게 번호로 묻고 전부 닫은 뒤 "확정"

### 2-5. 기능 명세
- [ ] 0장 상수·용어(값·출처), 1장 데이터 모델(TS 인터페이스), 2장 화면 목록·라우팅, 3장 기능별 동작 + AC, 4장 파이프라인, 5장 비기능, 6장 테스트 매트릭스, 7장 오픈 이슈
- [ ] 엔진은 순수 함수, AC는 손으로 검산한 숫자
- [ ] 저장소 스키마(`createStore('<접두어>')`), 이벤트 로그(금액은 어떤 형태로도 넣지 않음)
- [ ] 문구 린트 금지어 3그룹(상품·권고·기타)과 화이트리스트

### 2-6. 화면 흐름
- [ ] mermaid 네비 맵 + 뒤로가기 규칙(첫 화면 = 종료)
- [ ] 공통 레이아웃(자체 헤더 없음, 배너는 스크롤 마지막 요소, 잠금은 자리표시자)
- [ ] 화면별 저해상도 와이어프레임, 플로우 시퀀스, **카피 일람(키·문구)** — 이 표가 `ko.json`의 원본이 된다
- [ ] 디자인 토큰은 net-pay 6장 공유, 컴포넌트 인벤토리에 재사용 출처 표기

- [ ] net-pay `package.json` scripts 복사: `check`(typecheck·lint:copy·test:run), `data:fetch`, `data:build`, `check:data`, `check:config`, `build`, `build:release`
- [ ] `apps-in-toss.config.ts`, `@apps-in-toss/web-framework` 3.3.x, Vite + React + TS, vitest
- [ ] `@ait/kit` import. 앱별 주입값: Storage 접두어, 광고 그룹 ID(`.env`), 금지어 사전, 앱 이름
- [ ] `.env`는 커밋 금지(루트 .gitignore). `VITE_SUPPORT_EMAIL`, `VITE_AD_REWARDED_ID`, `VITE_AD_BANNER_ID`
- [ ] 루트 README 표에 한 줄 추가

### 2-8. 데이터 파이프라인

- [ ] 개발용 합성 데이터에는 `dev: true` 플래그 + 화면 배너, 프로덕션 빌드 차단

### 2-9. 엔진 + 골든 테스트
- [ ] 순수 함수 + 단위 테스트(AC 그대로)
- [ ] 골든 케이스 20건 내외. 기대값은 원문 숫자 리터럴 산술 또는 공공 계산기 브라우저 조회 결과. `FACT_CHECK.md`에 조회 조건·결과·조회일 표로
- [ ] 절사·반올림 규칙을 원문(고시·계산기)과 맞추고 테스트로 고정. 부동소수 오차 가드(1원 미만 = 0)
- [ ] 단조성 가정은 측정으로 확인(net-pay 실수령은 연봉에 단조가 아니었다)

### 2-10. 화면 (앱인토스 플랫폼 규칙)
- [ ] 토스 네비게이션 바 사용, 자체 헤더·뒤로가기 버튼 없음. `backEvent` 가로채 라우팅, 첫 화면에서 `Screen.close`
- [ ] 라이트 모드 고정, 제스처 확대 비활성, 세이프 에어리어는 SDK 값
- [ ] 진입 즉시 바텀시트 금지, 입력창 자동 포커스 없음(키패드가 결과를 덮지 않게)
- [ ] 잠금 기능은 실제 수치를 DOM에 넣지 않음(자리표시자). 흐림 처리만 하면 접근성 트리에 남는다
- [ ] 외부 링크는 출처·고객문의만. 다른 미니앱은 `intoss://` 스킴만. 자사 앱 설치 유도 금지
- [ ] 문구 린트 통과, 모든 결과 화면에 기준일·면책, "공식/제공/인증" 오인 문구 금지
- [ ] 개인정보 한 줄("입력한 금액은 이 기기 안에서만 계산돼요"), 저장 전체 삭제 버튼

## 4. 저장소·세션 규칙

### 4-1. 세션 범위
여러 Claude 세션이 같은 저장소에서 다른 앱을 동시에 작업한다. 세션마다 **담당 앱 하나**를 정하고 아래 경로만 만진다.

| 구분 | 경로 | 할 수 있는 것 |
|---|---|---|
| 담당 앱 | `<app>/` | 수정·커밋 |
| 공용 패키지 | `packages/ait-kit/` | 수정·커밋. 바꾸면 모든 앱 `npm run check` 통과 확인 |
| 공통 문서 | `docs/`, `CLAUDE.md`, `README.md` | 수정·커밋 |
| 다른 앱 | `<other-app>/` | **읽기만.** 참고 코드는 담당 앱으로 가져와 쓰고 원본은 고치지 않는다 |

- 공용 패키지 변경이 다른 앱 코드 수정을 요구하면 직접 고치지 않고 사용자에게 알린다. 그 앱의 세션이 처리한다.
- 다른 앱의 미커밋 변경이 `git status`에 보이면 보고만 한다.

### 4-2. 커밋 규칙
- **커밋 범위 = 세션 범위.** 경로를 지정해 스테이징한다. `git add -A`, `git add .`, `git commit -a` 금지.
  ```bash
  git add <app> packages/ait-kit docs CLAUDE.md README.md
  git commit -m "<type>(<app>): <요약>"
  ```
- 커밋 메시지 접두어: `feat(<app>)`, `fix(<app>)`, `docs(<app>)`, `docs` (공통 문서), `chore(kit)` (공용 패키지).
- 커밋 전 `git status`에서 스테이징된 파일이 전부 세션 범위 안인지 확인한다.
- `.env`(ECOS 인증키, 광고 ID) 절대 커밋 금지. `*.ait`, `dist`, `.claude/`는 gitignore.

### 4-3. 그 밖에
- 루트가 git 루트, npm workspaces 모노레포(비공개 `eungbin/app-in-toss`). `npm install`은 루트에서.
- 문서는 앱 폴더 `docs/` 아래, 공통 문서만 루트 `docs/`.

## 6. 배운 것 (함정 목록 — 새 앱마다 추가)

- **ECOS는 통계표별 작성기관을 봐야 한다.** 한국은행 작성만 출처표시로 상업 가능. KOSPI는 한국거래소, 원자재는 IMF(비상업 한정), 해외지수는 OECD. 일별 통계표는 7개뿐이고 분봉 없음. (fx-replay)
- **인앱결제는 서버를 부른다.** 비소모품 복원에 토스 로그인 + mTLS 상태 조회 API. 그래서 v1.0 광고 → v1.1 결제로 분할. (fx-replay)
- **자체 헤더·뒤로가기 버튼은 체크리스트 위반.** 토스가 네비 바를 그린다. (fx-replay)
- **공공데이터포털 파일은 최신 개정판이 아닐 수 있다.** 국세청 간이세액표는 포털이 2024판, 최신은 홈택스·국가법령정보센터 별표. (net-pay)
- **법령 별표는 평문으로 자동 수집되고 조문은 안 된다.** `lsBylTextDownLoad.do` POST(bylSeq, title, mode=0). 조문 화면·홈택스·손택스·4대보험센터는 JS 앱. (net-pay, rent-calc)
- **계산 결과가 단조라고 가정하지 말 것.** 실수령은 연봉에 단조가 아니었다(표 상한 구간에서 낙폭). 역산은 격자 탐색 + 목표 달성 재확인. (net-pay)
- **절사·반올림은 원문 계산기와 맞춰야 한다.** 고용노동부는 1일 평균임금 소수를 유지한다. floor 하나로 66원이 틀렸다. (net-pay)
- **출시 번들에 테스트용 광고 그룹 ID 문자열이 남으면 반려된다.** kit이 테스트 ID를 모듈 최상위에서 참조해 트리셰이킹이 되지 않았다. 런타임에 실 ID로 덮어써도 심사는 번들 문자열을 본다. 설정 검사로는 못 잡으니 빌드 산출물을 직접 스캔한다. (fx-replay)
- **정산은 팝빌이 필수고 인증서 종류가 제한된다.** 은행 금융거래용은 불가, 전자세금계산서용은 가능. 매월 4영업일 마감, 2회 미승인 시 운영 중단. (공통)
- **가이드·안내형 앱은 만들지 않는다.** 독자가 개발자면 토스 안이 아니라 GitHub·블로그가 채널이다. (rent-calc 기획)
- **법정 상한은 적용 범위를 먼저 나눠야 한다.** 주임법 5%·전환율 상한은 갱신·존속 중에만, 신규 계약엔 없다. 첫 화면에서 모드를 고르게 하지 않으면 잘못된 판정을 내보낸다. (rent-calc)
- **병행 세션의 `git add -A`가 내 파일을 쓸어 담는다.** rent-calc 문서 5개가 net-pay 커밋 두 개에 섞여 들어갔다. 세션 범위와 커밋 범위를 같은 경로 목록으로 고정한다(4장). (공통)
- **사전 상담은 필수 단계가 아니다.** 세 앱 모두 사전 상담 없이 진행했다. 필요하면 SUBMISSION에 메시지 초안만 남긴다. (공통)
