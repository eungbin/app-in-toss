### 1-2. 상세 설명 — **이미 등록·승인됨, 손대지 않는다** (343자)

> 근무수첩은 근무지별 출퇴근 시간과 휴게시간을 기록하고 월별 근무시간과 예상 급여를 확인하는 서비스입니다.
> 근무지와 시급, 사업장 규모, 근로계약 일정을 등록한 뒤 달력에서 근무일을 선택해 출퇴근 시간, 휴게시간, 휴일근무, 추가수당을 입력할 수 있습니다.
> 입력한 기록을 바탕으로 기본급, 야간·연장·휴일 가산금액과 주휴수당을 계산합니다. 소득 유형과 4대보험 설정에 따라 예상 세금, 보험료와 실수령액도 함께 확인할 수 있습니다.
> 기록은 사용자의 기기에 저장되며 CSV 파일로 내보낼 수 있습니다. 계산 결과는 사용자가 입력한 근로계약과 공제 조건에 따른 예상 금액으로, 실제 급여명세서와 차이가 날 수 있습니다.

**구현이 이 설명을 덮는지 대조했다.** 한 군데만 어긋난다.

| 설명에 적힌 것 | 구현 | 판단 |
|---|---|---|
| 근무지별 출퇴근·휴게 기록 | 있다 (M01) | ✓ |
| 시급·사업장 규모 등록 | 있다 (M02) | ✓ |
| **근로계약 일정 등록** | **없다** | ⚠ 아래 |
| 달력에서 근무일 선택 | 있다 (카드 C) | ✓ |
| 휴일근무·추가수당 입력 | 있다 | ✓ |
| 기본급·야간·연장·휴일 가산 | 있다 (CE-2) | ✓ |
| 주휴수당 | 있다 (CE-3) | ✓ |
| 소득 유형·4대보험 설정 | 있다 (일반/일용/사업소득 + 보험 3토글) | ✓ |
| 예상 세금·보험료·실수령액 | 있다 (CE-5) | ✓ |
| 기기 저장 | 있다 (앱인토스 Storage) | ✓ |
| CSV 내보내기 | 있다 (US-4) | ✓ |
| 예상액 면책 | 있다 (홈 카드 B 하단, 설정 "계산 기준") | ✓ |

⚠ **"근로계약 일정"은 폼에 없다.** 구판 근무지 폼에도 없었다(LEGACY_SCREENS 2-5) — 그 상태로
앱 정보 심사를 통과했다. 그 자리를 **급여일 + 주휴수당 자동 계산 토글**이 대신하고, 주휴 조건은
계약상 소정근로일이 아니라 **기록된 주의 실근로시간 15시간**으로 판정한다는 것을 화면에
그대로 적었다("주 15시간 이상이고 기록한 날을 모두 출근한 주를 계산해요").

**상세 설명은 고치지 않는다.** 승인된 문구를 건드리면 앱 정보 심사가 다시 열린다. 계약 일정
입력을 v1.1 에 넣을지는 출시 후 판단하고, 넣을 때 설명도 함께 손댄다.

### 1-5. 스크린샷 구성안 (5장) — **새로 만든다**

콘솔 규격은 **세로형 636 × 1048 PNG, 최소 3장**. 등록된 것이 0장이다.

| 순서 | 화면 | 담을 것 |
|---|---|---|
| 1 | 홈 (기록 2~3건) | **이번 달 예상 실수령액 큰 숫자 + 급여 계산 카드.** 차별점이 첫 장에 있어야 한다 — 시급 계산기와 갈리는 지점은 "기록이 쌓이면서 실수령이 갱신된다"다 |
| 2 | 기록 시트 (야간) | 18:00~다음 날 02:00, "다음 날" 배지, 미리보기의 `야간 180분 +15,480원`. **계산이 보이는 지점** |
| 3 | 홈 아래쪽 | 근무 달력(점·금액 축약)과 근무 기록 목록. 기록장 성격 |
| 4 | 근무지 시트 | 시급·사업장 규모(5인 미만/이상)·소득 유형 3종. **정확성의 근거**가 어디서 오는지 |
| 5 | 설정 시트 | "계산 기준" 박스와 기기 저장 각주. **심사 방어 문구가 앱 안에 있다는 증거** |

촬영·전처리 규칙은 [../../docs/RECOVERY.md](../../docs/RECOVERY.md) 6장 그대로.
- **출시 빌드에서 촬영한다.** 개발 전용 UI 가 보이면 안 된다.
- 사람 얼굴·타사 로고를 쓰지 않는다 (이 앱은 해당 없음 — 숫자와 폼뿐이다).
- 안드로이드 648×1390 → 위 44px(상태바) 잘라내기 → 걸쳐 있는 요소 위에서 아래를 끊기 →
  세로는 그대로 두고 좌우로만 넓혀 636×1048 → LANCZOS → PNG.
- **전처리 전에 화면에 찍힌 값이 맞는지부터 읽는다.** photo-standard 는 스크린샷을 검수하다
  형식 오표기를 발견했다.

이 앱에서 특히 검수할 값: 야간 분·가산액, 주휴 `n회`·"예정", 세전−공제=실수령, 달력 축약(`83천`).

### 1-6. 출시 노트 (검토 요청 시) — 530자

**콘솔 검토 요청 화면에서만 입력한다.** `ait deploy -m` 은 `memo`(배포 메모, **120자**)를
채우고 `releaseNote` 는 비워 둔다(photo-standard 에서 확인한 사실, PLAYBOOK 6장).

> 근무 기록과 예상 실수령액 확인 기능을 새로 만들었습니다. 앱 정보는 이미 승인된 상태이고 번들은 이번이 첫 출시입니다.
>
> 근무지에 시급, 사업장 규모, 급여일, 소득 유형을 등록하고 달력에서 날짜를 눌러 출퇴근 시간, 휴게시간, 휴일근무, 추가수당을 적습니다.
>
> 계산 근거를 화면에 표시합니다. 연장·야간·휴일 가산은 근로기준법 제56조, 주휴수당은 제55조 제1항과 시행령 제30조를 따랐고, 상시 4명 이하 사업장에 가산 규정이 적용되지 않는 것은 시행령 별표 1을 반영했습니다. 시급 기본값은 고용노동부 고시 최저임금이며, 공제는 국세청 간이세액표와 사회보험료율 고시를 씁니다.
>
> 결과는 입력한 조건에 따른 예상액입니다. 최저임금 미달이나 임금 체불 같은 판정은 하지 않고 수치와 기준만 보여 줍니다.
>
> 서버가 없습니다. 기록은 기기에만 저장하고 사용자가 직접 CSV로 내보낼 수 있습니다.
>
> 수익은 인앱 광고뿐입니다. 보상형 광고의 보상은 근무지 추가와 지난 기록 조회를 자정까지 여는 것이며 현금성 보상, 경쟁, 확률형 요소가 없습니다.

**길이 상한을 모른다.** 상세 설명은 500자인데 출시 노트 상한은 확인하지 못했다. 콘솔이
거절하면 마지막 문단을 이렇게 줄인다(−60자): "수익은 인앱 광고(보상형·배너)뿐이고 현금성
보상·경쟁·확률형 요소가 없습니다."

**금지어를 쓴 자리가 하나 있다.** "최저임금 미달이나 임금 체불 같은 판정은 하지 않고" —
`lint-copy` 가 앱 문구에서 막는 어휘를 **부정형으로** 썼다. 심사 담당자에게 이 앱이 무엇을
하지 않는지 전하는 가장 짧은 문장이고, photo-standard 출시 노트도 "배경 제거·보정 기능은
넣지 않았습니다"로 같은 형태를 썼다.

## 2. 심사에서 물을 만한 것

이 앱의 렌즈는 **노무**다. 다른 네 앱에 없던 것이다.

| 질문 | 답 |
|---|---|
| 계산 근거가 무엇인가 | 근로기준법 제50·55·56조와 시행령 제30조·별표 1, 고용노동부 고시 최저임금, 국세청 간이세액표, 공단·복지부 고시 사회보험료율. 조문 원문 대조 기록은 `docs/FACT_CHECK.md` 에 있고 설정의 "계산 기준" 박스에 표시한다 |
| 5인 미만 사업장을 구분하나 | 한다. 시행령 별표 1 의 제4장에 제54조·제55조 제1항·제63조만 있어 **가산은 적용하지 않고 주휴수당은 적용한다.** 근무지마다 규모를 고르게 한다 |
| 노무 상담·자문인가 | 아니다. 모든 금액은 "입력한 조건에 따른 예상액"이고 결과 화면에 고정 노출한다. **최저임금 미달·체불 판정을 하지 않는다** — 시급이 최저임금보다 낮아도 각주로 그 해 수치만 보여 준다. 금지어는 빌드에서 막는다(`lint-copy`, `check:bundle`) |
| 출퇴근을 자동으로 잡나 | 아니다. 위치·시각을 수집하지 않는다. 사용자가 직접 적는 수첩이다. 기기 권한을 하나도 요청하지 않는다(`apps-in-toss.config.ts` 의 `permissions: []`) |
| 근무지 이름·시급을 어디에 저장하나 | 앱인토스 Storage(기기)만. 서버가 없다. 설정에 전체 삭제가 있고, CSV 는 사용자가 직접 눌렀을 때만 기기 밖으로 나간다 |
| 로그에 무엇을 담나 | 개수·종류만. **금액·근무지 이름·시각을 넣지 않는다**(FUNCTIONAL_SPEC 3-17) |
| 금융 상품을 연결하나 | 하지 않는다. 급여 선지급·대출·카드·보험 어떤 상품도 없다. 외부 링크는 법령·고용노동부 출처와 고객문의 이메일, 같은 개발자의 `intoss://` 미니앱뿐이다 |
| 광고 보상이 무엇인가 | 기능 해제 하나. 근무지 2개 이상과 3개월 이전 기록 조회를 **기기 로컬 자정까지** 연다. `userEarnedReward` 에서만 지급하고 현금성 보상은 없다. 첫 근무지·기록·실수령·CSV·공유 카드는 잠그지 않는다 |
| 배너를 어디에 두나 | 홈 스크롤의 마지막 요소. 시트·입력 중·로딩에 광고가 없고 진입 즉시 뜨는 것도 없다 |
| 계산이 틀리면 | 골든 테스트 64건이 조문의 숫자를 손으로 곱한 값과 대조한다. 화면에 시간 분해(야간 n분·연장 n분)를 노출해 사용자가 검산할 수 있게 했다 |

### 3-2. 사용자만 할 수 있는 것 (콘솔·기기)

1. **광고 그룹 2개 발급** — 콘솔 → 인앱 광고 → 생성하기. 리워드·배너.
   현재 광고 그룹이 **0개**다. 실 ID 는 `.env` 에만 넣고 커밋하지 않는다.
2. **주요 기능 등록** — 1-4 의 값. 현재 0개다.
3. **스크린샷 5장** 촬영(출시 빌드에서) → 전처리 → 등록. 현재 0장이다.
4. **출시 빌드·배포** — `npm run build:release` → `npm run deploy:release`
   (`work-journal` 배포 키 프로필이 없으면 `npx ait token add work-journal` 을 먼저)
5. **그 번들로 QR 테스트 1회** — `isTested` 가 서야 검토 요청이 열린다.
   **리워드 광고를 끝까지 시청하지 않는다** — 자기 광고에 자기 노출을 만든다.
6. **검토 요청** → 출시 노트 입력(1-6) → 승인 → **출시 버튼**

### 3-3. 되돌릴 수 없는 것

- **출시는 사용자에게 즉시 반영된다.** QR 테스트를 통과한 뒤 누른다.
- **SDK 3.x 번들을 출시하면 2.x 로 롤백할 수 없다**(개발자 문서 명시). 이 앱은 2.x 를
  출시한 적이 없어(`isSdk3Deployed: false`, 구판 번들은 "검토 필요"에서 멈췄다) 돌아갈 대상
  자체가 없으므로 실질 손해는 없다.
- 앱 이름·부제·카테고리·키워드·상세 설명을 고치면 **앱 정보 심사가 다시 열린다.** 지금은
  승인 상태이므로 손대지 않는다.
