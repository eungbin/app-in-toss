## 1. 서비스 정의

### 1-1. 한 줄 정의
근무지별로 출퇴근·휴게를 달력에 기록하면 **이번 달 근무시간과 예상 실수령액이 바로 보이는** 시급 근로자용 근무 기록장. 기본급·야간·연장·휴일 가산·주휴수당을 근로기준법 수치로 계산하고, 소득 유형과 4대보험 설정에 따라 세금·보험료를 뺀 실수령을 보여 준다. 기록은 기기에만 저장되고 CSV 로 내보낼 수 있다.

### 1-2. 무엇이 아닌가 (심사 대응의 출발점)
- **급여명세서·노무 자문이 아니다.** 모든 금액은 "입력한 근로계약과 공제 조건에 따른 예상액"이다(등록된 상세 설명 마지막 문장). "체불"·"위반" 같은 단정을 하지 않는다.
- **출퇴근 인증·근태 관리가 아니다.** 위치·시각을 자동으로 잡지 않는다. 사용자가 직접 적는 수첩이다.
- **금융 상품을 팔거나 연결하지 않는다.** 급여 선지급·대출·카드 어떤 상품도 없다.
- **개인정보를 수집하지 않는다.** 근무지 이름·시급·기록은 기기 안에만 있다. 서버가 없다.
- 게임이 아니다. 랭킹·현금성 보상·확률 요소가 없다.

### 1-3. 왜 이 조합인가
1. **수요**: 알바·시급 근로자의 "이번 달 얼마 받지"는 매달 반복되는 질문이다. 검색 키워드 10개(근무·근무시간·알바·아르바이트·시급·급여·월급·주휴수당·실수령액·출퇴근)가 그 질문의 어휘다.
2. **문맥**: 토스 사용자는 급여 통장을 보며 들어온다. 통장에 찍힐 금액을 미리 보는 것이 자연스럽다.
3. **차별점**: 시급 계산기는 "시급 × 시간" 한 번 계산으로 끝난다. 이 앱은 **기록이 쌓이면서 실수령이 갱신**되고, 주휴·가산·공제까지 한 화면에서 보인다. 기록장이면서 계산기다.
4. **재사용**: 공제 엔진(net-pay)·광고·저장·네비(kit)·빌드 가드(photo-standard)가 이미 있다. 새로 만드는 것은 시간 → 급여 엔진과 화면이다.

### 1-4. 타깃 사용자
- 시급으로 일하는 알바·단시간 근로자. 근무지가 1~2개.
- 야간·주말 근무가 섞여 "가산이 붙는지" 헷갈리는 사람.
- 급여일에 통장 금액과 내 계산을 맞춰 보고 싶은 사람.

### 1-5. 성공 지표 (출시 후 90일)
1회성 도구가 아니라 **기록장**이므로 재방문이 핵심 지표다(photo-standard 와 반대).

| 지표 | 목표 | 측정 |
|---|---|---|
| 첫 세션 기록 생성률 | 50% | `record_saved` / 신규 유저 |
| 주 1회 이상 기록 유저 비율 (기록 유저 중) | 30% | `record_saved` 주별 유니크 |
| 30일 재방문율 | 25% | 앱인토스 홈 대시보드 |
| 리워드 시청률 (게이트 진입자 중) | 30% | `ad_reward_earned` / `gate_view` |
| 공유 카드 생성률 (월 집계 조회자 중) | 5% | `share_card_created` |
| 심사 | 1차 제출 반려 0건 | 콘솔 |

## 2. 심사 대응 원칙 (설계 제약)

### 2-1. 원칙 A — 금융 상품과의 거리
| 규칙 | 구현 |
|---|---|
| A1 | 급여 선지급·대출·카드·보험 상품명·유형 어느 것도 화면에 없다. "이 실수령이면 대출 한도는" 류 파생 금지 |
| A2 | 카테고리는 이미 생활 > 편의 > 도구 |
| A3 | 외부 링크는 법령·고용노동부·공단 출처와 고객문의 이메일만. 토스 금융 서비스 딥링크 없음 |
| A4 | 토스 자체 자산·급여 조회 영역으로 확장하지 않는다 |

### 2-2. 원칙 B — 노무·세무 자문이 아닌 참고 계산
| 규칙 | 구현 |
|---|---|
| B1 면책 고정 | 홈 급여 계산 카드·기록 시트·설정에 "예상액이며 실제 급여명세서와 다를 수 있어요" 계열 문구. 구판 문구 재사용(LEGACY_SCREENS 2-3 "계산 기준") |
| B2 기준 표기 | 설정 "계산 기준" 박스: 최저임금 연도, 근로기준법 주휴·가산 기준, 간이세액표 시행일, 사회보험료율 연도 |
| B3 단정·권고 금지 | "체불", "위반", "신고하세요", "최저임금 미달" 판정 문구 없음. 시급이 최저임금 아래여도 각주로 최저임금 수치만 보여 준다. 금지어는 `lint-copy` 로 차단 |
| B4 5인 미만 명시 | 5인 미만 사업장에서는 가산이 붙지 않는 이유(근로기준법 제11조)를 근무지 폼 각주로. 가산 행은 "참고액" 표기 |
| B5 주휴 조건 명시 | "주 15시간 이상, 기록된 날 모두 출근한 주" 를 토글 각주로. 계약상 소정근로일과 다를 수 있음을 적는다 |

### 2-3. 원칙 C — 개인정보 최소화
| 규칙 | 구현 |
|---|---|
| C1 | 서버 없음. 네트워크는 광고 SDK 만 |
| C2 | 근무지·기록은 앱인토스 Storage. 설정에 **전체 삭제** 제공. CSV 는 사용자가 직접 내보낼 때만 기기 밖으로 나간다 |
| C3 | 식별은 `loadAnonProfile` 만. 토스 로그인 없음 |
| C4 | 이벤트 로그에 금액·근무지 이름·시각을 넣지 않는다. 개수·종류만 |
| C5 | 문구: 설정 "근무지와 근무 기록은 외부 서버로 전송하지 않고 이 기기에만 저장해요"(구판 문구) |

### 2-4. 원칙 D — 광고 보상은 기능 잠금 해제만
| 규칙 | 구현 |
|---|---|
| D1 | 보상은 "오늘 하루 열기" 하나. 현금성 없음 |
| D2 | `userEarnedReward` 에서만 해제. `dismissed` 만으로 해제 금지 |
| D3 | 배너는 홈 스크롤 마지막. 시트·입력 중·로딩에 광고 없음. **진입 즉시 어떤 시트도 자동으로 열지 않는다 — 예외 없다.** 근무지 시트를 예외로 뒀다가 2026-09-10 심사에서 반려됐다 |

### 2-5. 콘솔 상세 설명
**이미 등록·승인된 원문을 그대로 둔다**(PROJECT_CONTEXT 3-2). "근로계약 일정을 등록" 문구는 급여일·주휴 토글로 갈음되지만 구판도 그랬으므로 유지한다. 출시 노트는 SUBMISSION 에서 따로 쓴다.

## 3. 핵심 사용자 흐름

```
홈 (월 단위)
 ├─ ‹ 월 › 네비 ── 3개월 이전 월 ◀ 게이트
 ├─ 카드 A  이번 달 예상 실수령액 ─ 세전 / 주휴 / 공제       ─ [카드로 공유] (무료)
 ├─ 카드 B  급여 계산 (n시간 · n일)
 │      근무 급여 / 가산(연장·야간·휴일) / 주휴수당 n회 / 추가수당 / 세전 / 소득세·지방 / 4대보험 / 실수령
 ├─ 카드 C  근무 달력 ── 날짜 탭 → 기록 시트(그 날짜)
 ├─ 카드 D  근무 기록 목록 ── 항목 탭 → 기록 시트(수정·삭제)
 ├─ 배너
 └─ 고정 버튼 [+ 근무 기록하기] → 기록 시트(오늘)
설정 시트 (⚙)
 ├─ 근무지 목록 · 추가 ── 2번째부터 ◀ 게이트 ── 근무지 시트
 ├─ 내 데이터: CSV 로 내보내기 / 전체 삭제
 └─ 계산 기준 · 출처 · 고객문의
첫 진입(근무지 0개) → 근무지 시트가 먼저 열린다
```

### 3-1. 첫 진입
근무지가 없으면 홈 대신 **근무지 시트**를 연다(기본 시급 = 올해 최저임금). 저장하면 홈으로, 홈은 0원 상태에서 "달력에서 날짜를 누르거나 아래 버튼으로 추가해 보세요".

### 3-2. 기록
기록 시트: 근무지(1개면 숨김) · 날짜 · 출근 · 퇴근 · 휴게(분) · 추가수당(원) · 휴일 근무 토글 · 메모. 입력 즉시 미리보기: 실근무 / 기본급 / (조건부) 연장·야간·휴일 가산 / 추가수당 / **예상 급여**. 저장 → 홈 갱신. 같은 날 같은 근무지 기록은 여러 건 허용(분할 근무).

### 3-3. 홈 = 결과
카드 A 의 큰 숫자가 메인 훅이다. 카드 B 가 그 숫자의 근거다. 진행 중인 주의 주휴는 합계에 넣지 않고 "이번 주 주휴 예정" 한 줄로 보여 준다(주가 끝나야 확정).

### 3-4. 공유 카드 (무료)
카드 A 의 [카드로 공유] → 1080×1350 이미지: "9월, 42시간 일하고 / 예상 실수령 512,340원" + 근무지 수 · 기준 문구 · 앱 딥링크. 금액 숨김 토글(시간만 보이기). `saveCardImage` + `shareLink`.

### 3-5. 게이트
- 무료(항상): 근무지 1개, 이번 달·지난 2개월 조회, 기록 무제한, 공제·실수령, CSV, 공유 카드.
- 게이트(리워드 → 자정까지): 근무지 2개 이상 등록·선택, 3개월 이전 월 조회. 광고 1회로 둘 다 열린다. 잠긴 근무지의 **기록은 지워지지 않고** 합계에서만 빠지며 "잠김" 표시.
- 잠금 카드 탭 → 바텀시트 "광고 보고 오늘 하루 열기". 실패 시 "지금은 광고를 불러올 수 없어요" 후 복귀.

## 4. 기능 요구사항

우선순위: **P0 = 출시 필수**, P1 = 출시 후 4주, P2 = 검증 후.

### 4-1. 계산 엔진 (P0) — 순수 함수, 골든 테스트

| ID | 요구사항 |
|---|---|
| CE-1 | **하루 기록 → 시간 분해** `splitShift(rec) → { work, night, overtime, holiday }` (분 단위). 실근무 = 퇴근 − 출근 − 휴게. 퇴근 ≤ 출근이면 다음 날로 본다(최대 24h). 야간 = 22:00~06:00 과의 겹침에서 **휴게를 먼저 차감**. 연장 = max(0, 실근무 − 8h). 휴일 토글이면 실근무 전체가 휴일근로, 8h 초과분은 별도 집계 |
| CE-2 | **하루 급여** `dayPay(split, workplace) → { base, overtimePay, nightPay, holidayPay, extra, total }`. base = 실근무 × 시급. 5인 이상만: 연장 × 시급 × 50%, 야간 × 시급 × 50%(연장과 중복), 휴일 8h 이내 × 50% · 초과 × 100%(휴일이면 연장 가산은 붙이지 않는다 — 휴일 초과 100% 가 그것이다). 5인 미만은 가산 0, 시간은 그대로 표시. extra = 추가수당 입력값 |
| CE-3 | **주휴수당** `weeklyHoliday(records, workplace, week) → { eligible, hours, pay, settled }`. 주 = 월~일. 자동 계산 토글 켬 + 그 주 실근로 ≥ 15h → eligible. hours = min(8, 실근로 ÷ 40 × 8) (소수 둘째 자리 절사), pay = hours × 시급. 주의 마지막 날이 오늘 이전이면 `settled: true`. **월 귀속 = 그 주 일요일이 속한 월** |
| CE-4 | **월 집계** `monthSummary(records, workplaces, month, today)`. 기록의 월 귀속은 **출근 날짜**. 근무지별 세전 = Σ dayPay.total + Σ settled 주휴. 시간·일수는 전 근무지 합 |
| CE-5 | **공제** `deductions(workplace, grossMonthly)`. 일반 근로: net-pay `computeNet` 을 **월 단위 진입점**으로 감싼다(연봉 = 월 × 12 경로가 간이세액표 월 구간과 일치함을 테스트로 고정). 4대보험은 토글별 on/off, "월 보험 신고 보수" 가 0 보다 크면 보험 산정 기준을 그 값으로 대체(소득세는 실제 세전 기준). 간이세액표 비율 80/100/120 반영. 사업소득: 세전 × 3% + 지방 0.3%, 보험 0. 일용 근로: 일별 (일급 − 150,000)⁺ × 6% × (1 − 55%) → 1,000원 미만 소액부징수, 지방 10%, 보험 0 |
| CE-6 | **다중 근무지 합산**. 공제는 근무지별로 계산 후 합산(사업장별 원천징수와 같다). 잠긴 근무지는 제외 |
| CE-7 | **금액 절사**는 net-pay `money.ts` 규칙을 그대로(국민연금 원 단위, 나머지 10원). 시간 → 급여는 원 단위 절사 |
| CE-8 | **골든 테스트**: 근로기준법 원문 산술로 ≥ 20 케이스(평일 8h / 9h 연장 / 야간 걸침 22~02 / 자정 넘김 18~02 휴게 60 / 휴일 6h / 휴일 10h / 5인 미만 동일 케이스 / 주 15h 경계 14.5·15·16h / 주휴 8h 상한 / 월 경계 주). 공제는 net-pay 골든 그대로 + 구판 화면 값 82,560·165,120 재현(LEGACY_SCREENS 3장). FACT_CHECK.md 에 기록 |
