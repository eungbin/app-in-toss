# "근무수첩" — 근무 기록·예상 실수령 앱 프로젝트 컨텍스트

> 이 문서는 **콘솔에 등록만 되어 있고 소스가 없는 앱**을 되살리기 위한 인계 문서다(2026-09-09).
> 2장의 `※` 항목은 콘솔 등록값이라 재논의하지 않는다. 그 밖의 결정은 6장 "확인 필요" 가 닫히면 확정된다.
> 다섯 번째 앱이지만 **신규가 아니라 복구**다. 선행 복구: [photo-standard](../../photo-standard/docs/PROJECT_CONTEXT.md). 절차: [RECOVERY.md](../../docs/RECOVERY.md).

## 1. 한 줄 정의

**토스 앱인토스 미니앱** "근무수첩"(폴더·appName `work-journal`, 영문명 `Work Journal`). 근무지별로 출퇴근·휴게를 달력에 기록하면 **이번 달 근무시간과 예상 실수령액이 바로 보이는** 알바·시급 근로자용 근무 기록장이다. 기본급·야간·연장·휴일 가산·주휴수당을 근로기준법 수치로 계산하고, 소득 유형과 4대보험 설정에 따라 세금·보험료를 뺀 실수령을 보여 준다.

## 3. 복구 맥락

### 3-1. 전제가 바뀌었다
RECOVERY.md 8장은 이 앱을 "출시돼 있는 앱" 으로 적었다. 콘솔 확인 결과 **앱 정보만 승인됐고 번들은 2026-07-19 테스트 업로드 2개("검토 필요")에서 멈췄다.** 홈 대시보드는 비활성, 광고 그룹 0개, 스크린샷 0장, 주요 기능 0개. 즉 지표도, 유저도, 구판 화면도 없다. 지켜야 할 것은 콘솔 등록값뿐이고 나머지는 백지다.

### 3-2. 남은 요구사항 — 등록된 상세 설명 원문
> 근무수첩은 근무지별 출퇴근 시간과 휴게시간을 기록하고 월별 근무시간과 예상 급여를 확인하는 서비스입니다. 근무지와 시급, 사업장 규모, 근로계약 일정을 등록한 뒤 달력에서 근무일을 선택해 출퇴근 시간, 휴게시간, 휴일근무, 추가수당을 입력할 수 있습니다. 입력한 기록을 바탕으로 기본급, 야간·연장·휴일 가산금액과 주휴수당을 계산합니다. 소득 유형과 4대보험 설정에 따라 예상 세금, 보험료와 실수령액도 함께 확인할 수 있습니다. 기록은 사용자의 기기에 저장되며 CSV 파일로 내보낼 수 있습니다. 계산 결과는 사용자가 입력한 근로계약과 공제 조건에 따른 예상 금액으로, 실제 급여명세서와 차이가 날 수 있습니다.

읽어낸 구조: **근무지**(시급·사업장 규모·계약 일정) → **달력 기록**(출퇴근·휴게·휴일·추가수당) → **월별 집계**(기본급·가산·주휴) → **공제**(소득 유형·4대보험) → **실수령** → **CSV**.
"사업장 규모" 가 있는 이유는 5인 미만 사업장에 가산수당 규정이 적용되지 않기 때문이다(4-2). 구판 설계자가 이 차이를 알고 있었다.

### 3-3. 구판 화면 기록 (2026-09-09 추가)
사용자가 QR 테스트 번들을 실기기에서 열어 11장을 찍었다 → [LEGACY_SCREENS.md](LEGACY_SCREENS.md). 홈 1화면 + 시트 3종(근무 기록·설정·근무지 등록) 구조, 기록 시트 필드 7개, 근무지 폼 필드 14개, 골든 값 4건. **근무지 폼에 근로계약 일정이 없다** — 주휴 판정은 기록된 주의 시간으로 한다. 공제는 구판(27,650)과 net-pay 엔진(32,355)이 다르고, **net-pay 엔진을 따른다**(LEGACY_SCREENS 3-1).

### 3-4. 선행 앱과의 관계
- **net-pay("세후로 말해줘")** 가 이미 4대보험 요율·간이세액표·공제 엔진을 가지고 있다. **월급 → 실수령** 계산은 그대로 쓰고, 이 앱은 그 앞단(**시간 기록 → 월급**)을 만든다. 코드는 세션 규칙대로 **복사해서 담당 앱에 쓴다.** kit 로 올리지 않는다(다른 앱 세션 범위).
- 부제가 약속한 "실수령액" 은 net-pay 엔진이 이미 골든 테스트로 증명한 값이다. 이 앱의 골든 테스트는 **시간 → 급여** 구간에 집중한다.

## 4. 계산 규칙 (요점 — FACT_CHECK 에서 원문 대조로 확정한다)

전부 법령 수치다. 골든 테스트 기대값은 net-pay·rent-calc 와 같이 **구현 코드를 거치지 않는 경로**(원문 숫자 리터럴 산술)로 만든다. 아래 수치는 착수 시 국가법령정보센터·최저임금위원회 원문으로 다시 확인한다.

### 4-1. 시간 집계
- 근로시간 = 퇴근 − 출근 − 휴게. 자정을 넘는 근무는 다음 날로 이어진다(야간 알바의 기본 케이스).
- **연장근로**: 1일 8시간 또는 1주 40시간 초과분(근로기준법 제50조·제53조).
- **야간근로**: 22:00 ~ 06:00 사이 근로(제56조 제3항). 연장과 **중복 적용**된다.
- **휴일근로**: 근로계약상 휴일(주휴일 등)의 근로. 8시간 이내 50%, 초과분 100%(제56조 제2항).

### 4-2. 가산수당 — 사업장 규모가 갈림길
- 연장·야간·휴일 가산 **50%**(휴일 8시간 초과 100%)는 **상시 5인 이상 사업장**에만 적용된다(제11조, 시행령 별표 1).
- 5인 미만은 가산 없이 통상시급 × 시간. 따라서 근무지 등록에 "5인 이상 / 5인 미만" 이 필수다.

### 4-3. 주휴수당
- 조건: 1주 **소정근로 15시간 이상** + 소정근로일 **개근**(제55조, 제18조 제3항, 시행령 제30조).
- 단시간 근로자 주휴시간 = (1주 소정근로시간 ÷ 40) × 8, 상한 8시간. 주휴수당 = 주휴시간 × 시급.
- "소정근로시간" 은 원칙상 계약상 시간이지만, 구판은 계약 일정을 받지 않고 **기록된 주의 근무시간 ≥ 15h + 기록된 날 전부 출근**으로 판정했다. 새 판도 같다(입력 부담 최소화). 주휴시간 계산의 분모는 그 주 실근로시간을 쓴다.

### 4-4. 최저임금
- **2026년 시급 10,320원**(2025년 10,030원) — 착수 시 최저임금위원회 고시로 확정. 시급 입력이 그 아래면 판정 표시 후보(6장 Q2).

### 4-5. 공제 — net-pay 엔진 재사용
- **근로소득**: 간이세액표(공제대상 가족 1인 기준) + 지방소득세 10%. 4대보험 근로자 부담분(국민연금·건강·장기요양·고용). net-pay `rates.json`·`tax-tables.json`·`computeNet` 복사.
- **사업소득(3.3%)**: 소득세 3% + 지방소득세 0.3%. 4대보험 없음.
- **일용근로소득**: 일 15만 원 공제 후 6% × (1 − 55%) — v1.0 포함 여부는 6장 Q3.
- 4대보험 적용 제외(월 60시간 미만 등)는 간단 토글로 두고 판정하지 않는다 — 자문이 되는 순간 심사 리스크다.

## 5. 심사 대응 원칙 (설계 제약)

1. **급여명세서·노무 자문이 아니다** — 모든 금액은 "입력한 계약 조건에 따른 예상" 이고 결과 화면마다 명시한다(상세 설명 마지막 문장이 이미 그렇다). "위반"·"체불" 같은 단정 표현을 쓰지 않는다. 문의 창구는 고용노동부 공적 링크만.
2. **금융 상품과의 거리** — 급여 선지급·대출·카드 어떤 상품도 노출·추천하지 않는다.
3. **개인정보 최소화** — 근무지 이름·시급·기록은 기기 안(앱인토스 Storage)에만. 서버 0, 계정 0. 이벤트 로그에 금액·근무지명을 넣지 않는다.
4. **광고 보상은 기능 해제만** — 현금성 보상 없음(net-pay 원칙).
5. **토스 네비 규칙** — 자체 헤더·뒤로가기 금지, backEvent 라우팅, 첫 화면 Screen.close ([[fx-replay-decisions]]).
6. 사전 상담은 하지 않는다. 카테고리는 이미 등록돼 있다.

## 6. 확인 필요 (PRD 전에 닫을 것)

**사용자 결정** — Q1~Q5 는 2026-09-09 사용자가 "전부 추천대로" 로 확정했다. 재논의하지 않는다.
- [x] **Q1. v1.0 기능 범위** — (a) 상세 설명 원문 그대로: 근무지·달력 기록·월별 집계·가산·주휴·공제·실수령·CSV. (b) CSV 제외. **추천이 (a) 로 바뀌었다**: 사용자 확인 결과 구판 CSV 는 실기기에서 실제 파일로 내보내졌다. SDK 3.x 에서 같은 경로가 되는지만 착수 시 확인하고, 안 되면 그때 (b) 로 내린다.
- [x] **Q2. 차별점(메인 훅)** — 부제가 이미 "한눈에" 를 약속하고, **구판 홈도 첫 카드가 "이번 달 예상 실수령액" 이었다**([LEGACY_SCREENS](LEGACY_SCREENS.md) 2-1). 후보: (a) **홈 첫 화면 = 이번 달 예상 실수령액 한 숫자** + 오늘 기록 버튼. (b) "주휴수당 받을 조건인가" 판정. (c) 시급 최저임금 미만 판정. **추천 (a) 를 훅, (b) 를 결과 카드 안 배지로.** (c) 는 자문 성격이 짙어 v1.0 제외 권고.
- [x] **Q3. 소득 유형** — (a) 근로소득 + 사업소득 3.3% 둘. (b) 일용근로소득까지 셋. **추천이 (b) 로 바뀌었다**: 구판 폼이 `일반 근로 | 일용 근로 | 사업소득` 셋이었고 상세 설명도 "소득 유형" 을 약속한다. 일용은 일 15만 원 공제 후 6% × 45% 로 단순하다.
- [x] **Q4. 광고 게이트** — 기록·집계·실수령은 무료. 게이트 후보: 근무지 2개 이상, 지난달 이전 기록 조회, 공유 카드. **추천: 근무지 2개 이상 + 3개월 이전 기록.** 광고 1회 = 자정까지 전체 해제(net-pay 방식).
- [x] **Q5. 공유 카드** — "이번 달 n시간 일해서 예상 실수령 n원" 카드를 넣는가. **추천 넣음**(유입 수단, 무료).
- [x] **Q6. 약관 등록** → 불필요(토스 로그인 전제 조건, STATUS.md). 원문: — 콘솔 홈에 "약관 등록하기 — 이동" 이 남아 있다. 사용자가 콘솔에서 확인·등록한다(다른 앱에서 어떻게 처리했는지 기억이 있으면 그대로).
