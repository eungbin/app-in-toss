## 전제가 바뀌었다 — 이 앱은 "출시된 앱"이 아니다

RECOVERY.md 8장은 이 앱을 photo-standard 와 같은 "출시돼 있는데 소스가 없는 앱"으로 적어 두었다.
2026-09-09 콘솔에서 직접 확인한 결과는 다르다.

| 확인한 것 | 사실 |
|---|---|
| 앱 정보 | **등록·승인 완료** ("앱이 승인되었어요. 출시하려면 '앱 출시' 메뉴로 이동해 주세요") |
| 번들 | 2026-07-19 에 **2개 업로드**(`20260719-1`, `20260719-2`, SDK 2.10.6). 둘 다 상태 **"검토 필요"**, 출시일시 없음 |

| 홈 대시보드 | **비활성** ("앱 출시 후 확인할 수 있어요"). 유저·리텐션 지표가 없다 |
| 인앱 광고 | 광고 그룹 **0개**, 데이터 없음 |

즉 **앱 슬롯과 앱 정보만 있고, 한 번도 출시된 적이 없다.** 소스는 없다(로컬 `~/dev`, GitHub 61개 저장소, git 이력 전부 확인).
따라서 이 건은 "복구"보다 **"등록된 슬롯에 첫 출시"** 에 가깝다. 달라지는 것:

- 지켜야 할 유저 인지도가 없다. 로고·화면 설계는 자유롭다. 다만 **콘솔 등록값(appName·이름·부제·카테고리·키워드)은 그대로 쓴다** — 바꾸면 앱 정보 심사를 다시 받는다.
- 구판 지표가 없으므로 "왜 안 됐나" 를 읽을 수 없다. 단서는 **등록된 상세 설명**(아래) 하나다.
- SDK 3.x 비가역 문제는 없다(2.x 로 출시된 적이 없다).

### 등록된 상세 설명 (원문, 유일한 기능 단서)

> 근무수첩은 근무지별 출퇴근 시간과 휴게시간을 기록하고 월별 근무시간과 예상 급여를 확인하는 서비스입니다.
> 근무지와 시급, 사업장 규모, 근로계약 일정을 등록한 뒤 달력에서 근무일을 선택해 출퇴근 시간, 휴게시간, 휴일근무, 추가수당을 입력할 수 있습니다.
> 입력한 기록을 바탕으로 기본급, 야간·연장·휴일 가산금액과 주휴수당을 계산합니다. 소득 유형과 4대보험 설정에 따라 예상 세금, 보험료와 실수령액도 함께 확인할 수 있습니다.
> 기록은 사용자의 기기에 저장되며 CSV 파일로 내보낼 수 있습니다. 계산 결과는 사용자가 입력한 근로계약과 공제 조건에 따른 예상 금액으로, 실제 급여명세서와 차이가 날 수 있습니다.

여기서 읽히는 구판 구조: 근무지(시급·사업장 규모·계약 일정) → 달력 기록(출퇴근·휴게·휴일·추가수당) → 월별 집계(기본급·가산·주휴) → 공제(소득 유형·4대보험) → 실수령 → CSV.

### 사용자 피드백 반영 (2026-09-09, 1차 QR 전)

1. **근무지가 없을 때 하단 버튼이 [근무지 등록하기] 로 바뀐다.** 비활성 버튼은 왜 안 되는지 알려 주지 않는다. 달력의 [기록 추가] 와 날짜 탭도 같은 곳으로 보낸다.
2. **시트를 아래로 끌어 닫을 수 있다.** 96px 또는 빠른 튕김. 손잡이·제목 줄에서만 시작한다 — 본문에서 끌면 스크롤과 다툰다.
3. **근무 시간이 겹치면 저장을 막는다.** 근무지를 가리지 않는다(한 사람이 같은 시간에 두 곳에 있을 수 없다). 자정을 넘는 기록은 절대 분 구간으로 환산해 비교한다. 맞닿은 구간(18:00 퇴근 / 18:00 출근)은 통과. 테스트 8건.
4. **월 네비 옆 설정 아이콘의 흰 배경 원을 뺐다.**

곁들여 고친 둘: 빈 상태의 `0분 · 0일` → `0시간 · 0일`, 포인터 캡처 실패가 시트를 굳히지 않게 감쌌다.
