## 1. 서비스 정의

### 1-1. 한 줄
사진을 고르고 용도를 고르면, **그 용도의 규격에 맞는지 판정하고 그 자리에서 맞춰 주는** 도구.

### 1-2. 해결하는 문제
온라인 여권 재발급, 비자 신청, 면허 갱신에서 사용자가 실제로 막히는 지점은 "사진을 어떻게 자르지"가 아니라 **"이 파일이 그 사이트에 올라가느냐"**다. 기준은 픽셀·용량·형식·비율 네 가지인데 기관마다 다르고, 사용자는 업로드에서 거절당하고 나서야 알게 된다.

### 1-3. 차별점 (하나)
**판정.** 사진을 넣으면 선택한 규격 대비 현재 상태를 항목별로 보여 준다 — 크기 OK / 용량 초과 / 비율 불일치. 흔한 리사이즈 앱은 "크기 조절"만 하고 통과 여부를 말해 주지 않는다.

### 1-4. 대상
토스 일반 사용자. 여권·비자·면허 등 온라인 민원에 사진을 올려야 하는 사람.

### 1-5. 성공 기준 (v1.0)
| 지표 | 목표 | 비고 |
|---|---|---|
| 저장 완료율 | 사진 선택 대비 50% 이상 | 핵심 퍼널. 중간 이탈이 크면 자르기 UI 문제 |
| 리워드 광고 시청률 | 상한 도달자의 30% 이상 | 상한이 너무 빡빡하면 이탈로 나타난다 |
| 재방문 | **KPI로 잡지 않는다** | 1회 쓰고 끝나는 도구다. 구판 리텐션 0%는 이 성격의 정상값일 수 있다 |

## 2. 심사 대응 원칙 (설계 제약)

### 2-1. 원칙 A — 사진은 기기를 벗어나지 않는다 (최우선)
개인정보 렌즈가 이 앱의 가장 큰 심사 리스크다. 얼굴 사진을 다루기 때문이다.

| 규칙 | 구현 |
|---|---|
| A1. 서버 0 | 사진을 업로드·전송·백업하지 않는다. 네트워크 호출은 앱인토스 SDK(광고)뿐 |
| A2. 저장 최소 | 원본·결과 이미지를 앱 저장소에 보관하지 않는다. 처리 후 메모리에서 버린다. Storage에는 마지막 프리셋 선택과 일일 사용 횟수만 둔다 |
| A3. 식별 | `User.getAnonymousKey` 만. 토스 로그인 없음 |
| A4. 문구 | 첫 화면 고정 한 줄: "사진은 이 기기 안에서만 처리돼요. 어디에도 올라가지 않아요." — 차별점이자 심사 설명 문구 |
| A5. 권한 | 앨범·카메라 권한은 **사용자가 그 행동을 누른 시점에만** 요청한다. 앱 진입 즉시 요청 금지 |

### 2-2. 원칙 B — 규격 안내이지 발급 보증이 아니다
기관 심사는 기관 재량이다. 앱이 "통과된다"고 말하는 순간 책임 범위를 넘는다.

| 규칙 | 구현 |
|---|---|
| B1. 보증 문구 금지 | "통과", "합격", "승인", "보장", "무조건" 금지. `lint-copy` 금지어 사전에 등록해 빌드에서 차단 |
| B2. 판정 표현 | 결과는 "기준에 맞아요 / 기준을 넘었어요"까지만. 발급·심사 결과를 예단하지 않는다 |
| B3. 면책 문구 고정 | 결과 화면 하단: "기관의 최종 심사 결과는 이 앱이 보장하지 않아요. 규격 기준은 아래 출처를 확인해 주세요." |
| B4. 출처·기준일 표기 | 프리셋마다 근거 기관명·URL·확인일 표시 |
| B5. 관행과 기준의 구분 | 증명사진 3×4cm 는 법정 근거가 없다. "일반 관행"으로 표기하고 기관 프리셋과 시각적으로 구분한다 |

### 2-3. 원칙 C — 편집의 한계를 지킨다
| 규칙 | 구현 |
|---|---|
| C1. 배경 제거 없음 | 외교부가 "배경색을 편집 프로그램으로 제거하여 변형된" 사진을 반려 사유로 명시 |
| C2. 보정 없음 | 얼굴 비율 변형·리터칭·필터 없음 |
| C3. 비율 왜곡 금지 | 리사이즈는 항상 비율을 유지한다. 목표 비율이 다르면 **자르기로만** 맞춘다. 늘리거나 눌러서 맞추지 않는다 |
| C4. 안내 문구 | 배경이 흰색이 아니면 "배경은 직접 촬영으로 맞춰 주세요"까지만 안내하고, 앱이 손대지 않는다 |

### 2-4. 원칙 D — 광고 보상은 사용 상한 해제만
| 규칙 | 구현 |
|---|---|
| D1. 보상 종류 | "오늘 저장 상한 열기" 하나. 포인트·현금성 보상 없음 |
| D2. 지급 조건 | `userEarnedReward` 이벤트에서만 지급. `dismissed` 만으로 지급 금지 (kit `ads.ts` 규약) |
| D3. 노출 위치 | 배너는 홈·결과 하단. 사진 선택 중·처리 중·자르기 화면에 광고 없음. 진입 즉시 광고 금지 |
| D4. 테스트 ID 차단 | 출시 번들에 테스트 광고 그룹 ID 문자열이 남으면 반려된다. kit 번들 스캔 가드를 채택 |

### 2-5. 콘솔 상세 설명 문구 (초안)

> "사진규격"은 여권·비자·운전면허 등 온라인 민원에 제출하는 사진을 각 기관이 공개한 규격에 맞추는 도구입니다.
> 사용자는 (1) 앨범이나 카메라에서 사진을 고르고, (2) 용도를 선택하면 현재 사진의 가로·세로 픽셀, 파일 용량, 비율이 그 규격에 맞는지 항목별로 확인할 수 있으며, (3) 자르기·크기 변경·용량 줄이기를 거쳐 규격에 맞는 파일로 저장할 수 있습니다.
> 모든 이미지 처리는 사용자의 기기 안에서 이루어지며, 사진은 어떤 서버로도 전송되거나 저장되지 않습니다. 배경 제거나 얼굴 보정 기능은 제공하지 않습니다. 기관의 최종 심사 결과를 보장하지 않으며, 규격 기준의 출처와 확인일을 화면에 표시합니다.
> 규격 출처: 외교부 여권안내, 도로교통공단, 미국 국무부.

> **수익 항목**: 인앱 광고 — 보상형(오늘 저장 상한 열기), 배너(홈·결과 하단). 토스 애즈 SSP만 사용. 인앱결제 없음.

## 3. 핵심 사용자 흐름

```
홈 ─(사진 고르기)─ 앨범 / 카메라
 │
 ├─ 프리셋 선택 (여권 온라인 · 여권 인화 · 운전면허 · 미국 비자 · 증명사진 · 직접 입력)
 │
 ▼
판정 화면 — 항목별 OK / 초과 / 불일치
 │
 ├─ 비율이 다르면 ─▶ 자르기 (비율 고정)
 │
 ▼
맞추기 (리사이즈 + 용량 압축)
 │
 ├─ 오늘 3장 초과? ─▶ 리워드 광고 시트 ─(userEarnedReward)─▶ 자정까지 해제
 │
 ▼
저장 완료 (기기 앨범)
```

가장 짧은 경로는 **사진 고르기 → 프리셋 → 저장** 세 번의 탭이다. 자르기는 비율이 어긋날 때만 끼어든다.

## 5. 데이터 소스 요구사항

외부 API·파이프라인이 **없다.** 규격 수치는 번들 상수다.

| 프리셋 | 기준 | 출처 | 확인일 |
|---|---|---|---|
| 여권(온라인) | 413×531 권장, 395–431 × 507–550 허용, JPG, 500KB 이하, 300dpi | [외교부 여권안내](https://www.passport.go.kr/home/kor/contents.do?menuPos=12) | 2026-09-08 |
| 여권(인화) | 3.5×4.5cm, 머리 3.2–3.6cm → 300dpi 환산 413×531 | [외교부 여권안내](https://www.passport.go.kr/home/kor/contents.do?menuPos=32) | 2026-09-08 |
| 운전면허(온라인) | 350×450 (3.5×4.5cm), 2016-02-01부터 여권 규격 적용 | [도로교통공단](https://www.safedriving.or.kr/guide/larGuide10.do?menuCode=MN-PO-12111) | 2026-09-08 |
| 미국 비자 | 600×600 ~ 1200×1200, **정사각 필수**, JPEG, 240KB 이하 | [US Dept. of State](https://travel.state.gov/content/travel/en/us-visas/visa-information-resources/photos.html) | 2026-09-08 |
| 증명사진 3×4 | 354×472 @300dpi — **관행, 법정 근거 없음** | — | — |

- 갱신은 드물지만 기관이 기준을 바꿀 수 있다. 상수 파일에 출처·확인일을 함께 두고, `check:data` 로 **확인일이 1년을 넘으면 빌드에서 경고**한다.
- 골든 테스트 기대값은 위 원문 수치의 **리터럴 산술**로 만든다. 구현 코드를 거치지 않는다.

| 프레임워크 | Vite + React + TypeScript (저장소 표준) |
| SDK | `@apps-in-toss/web-framework` **3.x** |
| 공용 | `@ait/kit` — 광고·저장·네비·백스택·공유·환경·i18n·세이프에어리어 |
| 이미지 처리 | **Canvas 2D.** `drawImage` 로 크롭·리사이즈, `toDataURL('image/jpeg', q)` 로 품질 조절 |
| 용량 맞추기 | 품질 `q` 에 대한 **이분 탐색** (약 8회). 목표 이하를 만족하는 최대 품질을 고른다 |
| 상태 | 앱 로컬 store (net-pay·rent-calc 구조 재사용) |
| 서버 | 없음 |

**성능 주의**: 고해상도 이미지를 Canvas로 다루면 메모리를 크게 쓴다. 입력 시 `maxWidth` 로 상한을 두고, 중간 캔버스를 재사용하며, 처리 후 참조를 끊는다. 저사양 안드로이드에서의 동작을 실기기로 확인한다.
