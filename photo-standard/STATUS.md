## QR 테스트에서 나온 것 (2026-09-09)

**사진 입력이 앨범·카메라 둘 다 실패했다.** 원인은 `ImageResponse.dataUri` 가 이름과 달리
**헤더 없는 순수 base64** 였던 것(`/9j/4AAQSkZJ…`). `img.src` 에 그대로 넣어 상대 경로로
해석됐다. 받는 즉시 `data:` 헤더를 붙여 정규화하도록 고쳤고 회귀 테스트 10건을 넣었다.

**형식 판정도 같이 망가져 있었다.** `dataUriMime()` 이 빈 문자열을 돌려줘 여권 프리셋에서
"형식: 기준과 달라요" 가 뜨고 있었다. 정규화로 함께 해결됐다.

브라우저에는 SDK 가 없어 이 차이가 드러나지 않는다. **실기기에서만 터지는 종류**라
PLAYBOOK 6장에 적었다.

**결과 화면이 형식을 잘못 찍고 있었다.** `format: 'any'` 프리셋(운전면허·여권 인화용·증명사진)은
JPEG 로 인코딩되고 파일명도 `.jpg` 인데, 화면에는 프리셋 설정을 보고 "PNG" 라고 썼다.
스크린샷을 검수하다 발견했다. 결과물의 실제 mime 을 쓰도록 고치고 회귀 테스트를 넣었다(81건).

**결과에서 [다시 자르기] 후 [이대로 맞추기] 를 누르면 자르기 화면에 갇혔다.** 변환이 끝날 때
`스택에 result 가 있으면 손대지 않는다` 로 짜여 있어, 재변환에서는 `crop` 이 맨 위에 남았다.
언제나 결과가 맨 위가 되도록 고쳤다. 겸사겸사 **직전에 자른 자리를 되살리도록** 했다 —
"다시" 자르기인데 처음부터 잡아야 하는 건 어색하다.

## 다음 한 걸음

복구는 끝났다. 이제 운영이다.

1. **정산 월간 승인** — 팝빌 역발행, 매월 4영업일 마감. **2회 미승인이면 미니앱 운영이 중단된다.**
   절차는 [../docs/SETTLEMENT.md](../docs/SETTLEMENT.md). 사업자 공통이라 네 앱이 같이 쓴다.
2. **광고 수익 확인** — 콘솔 → 인앱 광고 → 성과. 구판은 광고 미등록으로 0이었다.
   유저가 붙는지, 리워드 시청률이 상한 도달자의 30% 를 넘는지 본다(PRD 1-5).
3. **규격 출처 신선도** — `check:data` 가 확인일 1년에 경고, 2년에 빌드를 막는다.
   기관이 기준을 바꾸면 `src/data/presets.ts` 의 수치와 `checkedAt` 을 갱신하고 재배포·재심사한다.
4. **재방문은 KPI 로 잡지 않는다.** 1회성 도구다(PRD 1-5).
