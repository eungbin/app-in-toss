## 1. 서비스 정의

### 1-1. 한 줄 정의
과거의 실제 환율·금리 데이터를 하루 단위로 리플레이하면서 "그때 내가 원화를 달러로 바꿨다면 / 그대로 뒀다면"을 시뮬레이션하고, 플레이가 끝나면 **그 구간에 실제로 무슨 일이 있었는지 해설과 함께 내 판단을 복기**하는 콘텐츠 앱.

### 1-2. 무엇이 아닌가 (심사 대응의 출발점)
- 실시간 시세를 보여주는 앱이 아니다. **모든 데이터는 최소 12개월 이전의 과거 통계**다.
- 실제 환전·매매·계좌 연동이 없다. 화면의 자산은 전부 가상 포인트(P)다.
- 종목·통화·타이밍을 추천하지 않는다. 결과 화면은 "실제로 이런 일이 있었다"만 말하고 "그러니 이렇게 하라"는 절대 말하지 않는다.
- 게임이 아니다. 랭킹·연승·대결·확률형 보상이 없다. 배지와 복기 노트만 있다.

### 1-3. 왜 환율인가 (1단계 자산 선택 근거)
1. **라이선스**: 한국은행이 직접 작성한 통계(731Y003 원/달러 OHLC 1990~, 817Y002 시장금리 1995~)는 출처표시만으로 상업 이용이 가능하다. KOSPI는 KRX 승인이 필요하고 원자재는 일별 데이터가 없다.
2. **심사**: 환율은 "증권"이 아니다. 앱인토스 오픈 정책의 금융 서비스 금지 조항은 "대출·보험·카드·증권 등 금융 상품"을 대상으로 한다. 환율 복기는 여행·유학·해외직구라는 일상 맥락으로 설명할 수 있어 투자 자문 조항에서도 가장 멀다.
3. **콘텐츠성**: 1997 외환위기, 2008 금융위기, 2020 코로나, 2022 강달러 등 한국인이 체감한 사건이 원/달러 차트에 전부 들어 있다. 시나리오 팩(유료 콘텐츠)의 소재가 충분하다.
4. **데이터 크기**: 1990년 이후 원/달러 OHLC 약 9,000행. JSON으로 300KB 내외라 앱 번들에 그대로 넣을 수 있어 서버·CDN이 필요 없다.

### 1-4. 타깃 사용자
- 토스 사용자(만 19세 이상) 중 환율·경제 뉴스에 관심은 있지만 투자 앱은 부담스러운 20~40대.
- 하루 5~10분, 대중교통에서 한 판(2~3분) 단위로 소비.
- 페르소나: "달러 예금 들까 말까 고민만 3년째" / "2008년에 나는 뭘 했을까 궁금한 직장인" / "경제 상식 콘텐츠를 숏폼처럼 소비하는 사람".

### 1-5. 성공 지표 (출시 후 90일)

| 지표 | 목표 | 측정 |
|---|---|---|
| D1 / D7 리텐션 | 30% / 12% | 앱인토스 분석 대시보드 |
| 1인당 일 플레이 수 | 2.5판 | 자체 이벤트 로그 |
| 리워드 광고 시청률 (무료 소진 사용자 중) | 40% | `userEarnedReward` / 무료 소진 수 |
| 시나리오 팩 구매 전환 (팩 미리보기 진입자 중) | 3% | IAP 주문 완료 수 |
| 심사 | 1차 제출에서 금융 조항 관련 반려 0건 | 콘솔 반려 사유 |

## 2. 금융 조항 대응 원칙 (설계 제약)

앱인토스 서비스 오픈 정책 원문에서 이 서비스에 걸리는 세 조항과, 각각을 **설계 수준에서** 무력화하는 규칙.

### 2-1. 원칙 A — "현재"를 앱에서 완전히 제거한다
정책: "대출·보험·카드·증권 등 금융 상품 관련 서비스는, 법적 인허가 여부와 관계없이 … 등록할 수 없어요."

| 규칙 | 구현 |
|---|---|
| A1. 데이터 컷오프 | 번들에 포함되는 데이터의 마지막 날짜는 **빌드 시점 기준 12개월 이전**. 빌드 스크립트가 컷오프 이후 행을 물리적으로 제거하고, 테스트가 이를 검증한다. |
| A2. 현재가·환율 위젯 없음 | 오늘 환율, 실시간 차트, 외부 시세 링크를 어디에도 두지 않는다. 외부 링크는 ECOS 출처 링크와 고객문의 이메일만 허용. |
| A3. 실제 금융 행위 유도 없음 | "달러 예금 개설", "환전하기", 증권사·은행 딥링크, 토스 금융 서비스 연결 일체 없음. |
| A4. 용어 | 화면 용어는 "달러로 바꾸기 / 원화로 바꾸기 / 그대로 두기". "매수/매도/포지션/수익률 랭킹" 같은 증권 용어는 사용자 화면에서 배제. 결과 화면 지표명은 "결과 P", "만약 그대로 뒀다면 P". |

### 2-2. 원칙 B — 해설은 과거형·서술형만, 예측·권고 문장 금지
정책: "특정 종목 추천이나 투자 전략 안내로 개인 투자자의 의사결정에 영향을 미치는 서비스는 … 등록할 수 없어요."

| 규칙 | 구현 |
|---|---|
| B1. 문장 시제 | 모든 해설·복기 문구는 과거형 서술. "~했다", "~였다", "당시 ~라는 평가가 있었다". |
| B2. 금지 어휘 사전 | "지금", "타이밍", "사라/팔아라", "노리세요", "이럴 때는", "패턴이 나오면", "다음에는", "전략", "추천", "유망", "수익 내는 법". 빌드 시 해설 JSON에 대한 린트로 차단한다. |
| B3. 복기 문구 형식 | "당신은 Day 12에 달러로 바꿨다. 실제 그날은 2008-09-15, 리먼브러더스 파산 신청일이었다." — **사용자 행동 + 실제 사실**의 병치만 허용. "잘했다/아쉽다" 같은 평가도 넣지 않는다. |
| B4. 결과 비교 대상 | 벤치마크는 "그대로 뒀다면"(현금 보유) 하나. 다른 사용자와의 비교 없음. |
| B5. 유료 콘텐츠 | 시나리오 팩의 해설은 신문 기사·연표 형태의 사건 복기. 원칙 B1~B3 동일 적용. |

### 2-3. 원칙 C — 보상은 비금전, 경쟁 요소는 0
정책: "사행성 요소가 포함된 콘텐츠는 … 위법 소지가 있어요." + 게임 재분류 리스크.

| 규칙 | 구현 |
|---|---|
| C1. 보상 | 배지(비금전, 교환 불가), 복기 노트 저장. 포인트(P)는 판마다 초기화되며 누적·교환·이전되지 않는다. |
| C2. 경쟁 | 랭킹·리더보드·친구 비교·연승 없음. 공유 카드에도 "수익률"이 아니라 "나는 1997년 외환위기를 이렇게 지나왔다" 서술형 문구. |
| C3. 확률 | 랜덤 요소는 "무작위 구간 선택"만. 뽑기·확률형 아이템·보상 랜덤화 없음. |
| C4. 광고 보상 | 리워드 광고의 보상은 "플레이 1회 추가"만. 포인트·아이템 지급 없음(광고 소비를 보상과 직접 연결하는 구조 금지 정책 준수). |
| C5. 톤 | 첫 화면·결과 화면 헤드라인: "과거 차트로 배우는 판단 복기". 게임 UI 관용구(레벨, 콤보, 스테이지 클리어, 승리) 사용 금지. |

### 2-4. 심사 사전 상담용 서비스 설명 문구
채널톡 사전 상담과 콘솔 상세 설명에 그대로 쓴다. (콘솔 가이드가 요구하는 "서비스 접속 → 행동 → 결과" 흐름으로 작성)

> **서비스 설명**
> "그때 환전했다면"은 한국은행 경제통계시스템(ECOS)이 공개한 **과거 환율·금리 통계**를 하루 단위로 다시 재생하며 즐기는 판단 복기 콘텐츠입니다.
> 사용자는 자산명과 날짜가 가려진 과거 차트를 보며 가상 포인트를 "달러로 바꾸기 / 원화로 바꾸기 / 그대로 두기" 중 하나로 운용합니다. 플레이가 끝나면 실제 기간과 사건(예: 1997년 외환위기, 2008년 금융위기)이 공개되고, 그때 실제로 어떤 일이 있었는지 해설과 함께 자신의 선택을 되돌아봅니다.
> 본 서비스는 **실시간 시세·현재가를 일절 표시하지 않으며**(모든 데이터는 12개월 이상 지난 과거 통계), 실제 환전·매매·계좌 연동 기능이 없고, 특정 자산이나 시점을 추천하지 않습니다. 사용자 간 순위 경쟁, 현금성 보상, 확률형 요소가 없습니다.
> 데이터 출처: ECOS(한국은행) — 원화의 대미달러 환율(731Y003), 시장금리(817Y002), 기준금리(722Y001). 한국은행이 작성한 통계로 출처 표시 조건으로 상업적 이용이 허용됩니다.

> **결제 항목 목록 (인앱 결제, 전부 디지털 상품 — v1.1부터 적용, 사전 상담 시 전체 제시)**
> 1. 시나리오 팩 (비소모품, 각 1,500~2,900원): 특정 역사 구간의 플레이 + 사건 해설 챕터. 예) "1997 외환위기", "2008 글로벌 금융위기", "2020 팬데믹", "2022 강달러"
> 2. 프리미엄 (비소모품, 단건 4,900원): 광고 제거 + 일일 무료 플레이 제한 해제 + 복기 노트 무제한 저장
> 3. 인앱 광고: 보상형(플레이 1회 추가), 배너(홈·기록 화면 하단). 토스 애즈 SSP만 사용.

## 3. 핵심 사용자 흐름

```
홈 ─┬─ [오늘의 리플레이] 무작위 구간 (무료 3판/일)
    │      └─ 블라인드 플레이 (60거래일, 1일=2초) ─ 리빌 ─ 결과·복기 ─ 공유/저장
    ├─ [시나리오] 챕터 목록 (무료 1개 + 유료 팩)
    │      └─ 챕터 소개(사건 배경, 과거형) ─ 플레이 ─ 리빌(이미 알고 있음) ─ 해설 챕터
    ├─ [내 기록] 복기 노트, 배지, 플레이 이력
    └─ [설정] 데이터 출처·라이선스, 구매 복원, 고객문의
```

### 3-1. 한 판의 구조 (오늘의 리플레이)
1. **시작**: 자산 "?" , 시작 시점 "Day 1", 시작 가상 포인트 1,000,000 P (전액 원화 상태). 차트는 시작값 100 기준 정규화.
2. **진행**: 60거래일. 기본 속도 1일 = 2초(일시정지·2배속 가능). 매일 캔들이 하나 추가된다. 사용자는 아무 때나 "달러로 바꾸기(25/50/100%)", "원화로 바꾸기(25/50/100%)", "그대로 두기"를 선택. 전환 비용은 없다(스프레드·수수료를 넣으면 실제 환전 서비스로 오해될 소지가 있고, 콘텐츠 톤에 맞지 않음).
3. **종료 및 리빌**: Day 60에 자동 종료. 화면이 뒤집히며 자산명(원/달러 환율), 실제 날짜 구간, 그 기간의 주요 사건 마커가 차트 위에 표시된다.
4. **결과·복기**: 결과 P vs "그대로 뒀다면" P. 내 전환 시점들 위에 실제 사건 배지. 해설 3~5문장(과거형). 하단에 ECOS 출처 표기.
5. **다음**: 복기 노트 저장 / 공유 카드 만들기 / 한 판 더(무료 잔여 or 광고 보고 1회).

### 3-2. 무료·광고·결제 흐름
- 무료 플레이 3판/일 (자정 초기화, 기기 로컬 시간).
- 소진 시 바텀시트: "광고 보고 한 판 더" (리워드 광고) / "프리미엄 알아보기". 바텀시트는 사용자가 "한 판 더"를 눌렀을 때만 뜬다(진입 즉시 자동 오픈 금지 체크리스트 준수).
- 리워드 광고는 홈 진입 시 미리 로드(`loadFullScreenAd`), `userEarnedReward` 이벤트에서만 플레이 1회 추가.
- 시나리오 팩은 챕터 소개 화면까지 무료로 볼 수 있고, "플레이" 버튼에서 결제 시트.

## 4. 기능 요구사항

우선순위: **P0 = 출시 필수**, P1 = 출시 후 4주 내, P2 = 검증 후.

### 4-1. 리플레이 엔진 (P0)

| ID | 요구사항 |
|---|---|
| RE-1 | 일별 OHLC 시계열을 입력받아 Day 1..N 순서로 캔들을 추가 렌더링한다. N은 시나리오 정의값(기본 60). |
| RE-2 | 재생 속도 1x(기본 2초/봉, 시나리오별 `tickMs` 재정의 가능), 2x, 일시정지. 백그라운드 전환 시 자동 일시정지. |
| RE-2b | 타임프레임: 일봉·주봉·월봉. 주봉·월봉은 ECOS 일봉을 런타임 집계해 만든다. ECOS에는 일별보다 짧은 주기가 없으므로 분봉·시간봉은 제공하지 않는다. |

### 5-2. 수집·번들 파이프라인 (`scripts/fetch-ecos.ts`)
1. ECOS 인증키(무료)로 `StatisticSearch/{KEY}/json/kr/1/10000/731Y003/D/19900101/{CUTOFF}/{ITEM}` 호출. 항목별 1만 행 이내라 1~2회 호출로 끝난다.
2. 4개 항목(시·고·저·종)을 날짜 키로 병합 → `{ d: "19970103", o, h, l, c }[]`. 결손일(휴장)은 행 자체가 없으므로 그대로 둔다. 종가만 있고 시·고·저가 없는 날은 종가로 채우고 `f: true` 플래그.
3. **컷오프 필터**: `d <= today - 12개월`인 행만 남긴다. 테스트: 번들 내 최대 날짜가 컷오프 이하임을 CI에서 단정.
4. 출력: `src/data/usdkrw.json`, `src/data/cnykrw.json`, `src/data/baserate.json`, 각 파일 헤더에 `{ source: "ECOS 731Y003", org: "한국은행", fetchedAt, cutoff }`.
5. 시나리오 정의(`src/data/scenarios/*.json`)와 해설 문구는 수동 작성. 빌드 시 원칙 B 금지어 린트.
6. 재수집은 연 1회(컷오프 이동). 앱은 런타임에 ECOS를 호출하지 않는다(약관 제9조 ⑤ "계속적 제공 보장 안 함" 대비).

### 5-3. 출처 표기 (DATA_VERIFICATION.md 4절 확정)
- 결과·리빌 화면 하단: `출처: ECOS(한국은행, 원화의 대미달러 환율), 수집일 YYYY-MM-DD`
- 설정 > 데이터 출처: `자료 : ECOS>3.1.1.3. 원화의 대미달러, 원화의 대위안/대엔 환율` 등 통계표 정식 명칭 + ecos.bok.or.kr 링크
- 블라인드 플레이 중에는 표기하지 않는다(리빌 시 표기).
- "한국은행 공식/제휴/제공 게임" 류의 오인 문구 금지.

## 7. 기술 아키텍처

```
[빌드 타임]  ECOS API ──fetch-ecos.ts──▶ src/data/*.json (컷오프 적용, 출처 헤더)
                                            │
[앱 번들]   React + TS (Vite) + @apps-in-toss/web-framework
             ├─ engine/   리플레이 상태머신, 포지션 계산 (순수 함수, 단위 테스트)
             ├─ chart/    캔들 차트 (경량 canvas 렌더러, 외부 차트 라이브러리는 번들 크기 보고 결정)
             ├─ data/     시세 JSON, 시나리오 JSON, 해설 문구
             ├─ platform/ Storage, Ads, IAP, Share, AnonymousKey 래퍼 (모두 isSupported 가드)
             └─ screens/  홈, 플레이, 리빌·결과, 시나리오, 기록, 설정
[런타임 v1.0] 서버 없음. 네트워크 호출은 앱인토스 SDK(광고)만.
[런타임 v1.1] 최소 서버 1대(무료 티어): 토스 로그인 토큰 교환 · 사용자 userKey 조회 · IAP 주문 상태 조회(mTLS)
              └─ 엔드포인트 3개, 상태 저장 없음(DB 불필요). 결제 알림 URL 수신은 선택.
```

- **호스팅**: 앱인토스 번들 업로드(압축 해제 100MB 이하)이므로 별도 호스팅 불필요. 데이터 300KB급이라 번들 포함. Vercel/Cloudflare Pages는 QR 테스트·공유 OG 이미지 정도에만 사용(무료 티어).
- **저장**: 앱인토스 Storage API. 스키마 버전 필드 포함(마이그레이션 대비).
- **서버**: PROJECT_CONTEXT 6장의 "서버 불필요"는 **시세 데이터에 한해서는 그대로 맞다.** 그러나 인앱결제 문서는 기기 변경 복원에 토스 로그인 + 서버 간 주문 상태 조회(mTLS)를 요구하므로, **결제가 들어가는 순간 소형 서버가 필요하다.** 비용 0원 원칙은 유지된다(Cloudflare Workers 또는 Vercel Functions 무료 티어, DB 없음). 따라서 릴리즈를 둘로 나눈다.
  - **v1.0 (광고 전용)**: 서버 0, 토스 로그인 0. 무료 3판 + 리워드 광고 + 배너. 심사 부담 최소.
  - **v1.1 (결제 추가)**: 토스 로그인(`appLogin` → 서버에서 인가코드→AccessToken→userKey), IAP 상품·주문 상태 조회 서버 엔드포인트, mTLS 인증서 발급. 시나리오 팩·프리미엄 판매 개시.
  - 서버 엔드포인트(v1.1): `POST /auth/exchange`(인가코드→userKey), `GET /iap/owned`(userKey별 소유 상품 = 주문 상태 조회 결과), `POST /iap/notify`(결제 알림 URL, 선택).
- **분석**: 앱인토스 분석 대시보드 + 이벤트 로그 가이드에 따른 커스텀 이벤트(`play_start`, `convert`, `reveal`, `ad_reward_earned`, `iap_success`).
- **테스트**: 엔진·포지션 계산 단위 테스트, 컷오프·금지어 빌드 테스트, 앱인토스 샌드박스에서 결제 3시나리오(성공 / 결제 성공+지급 실패 / 취소·오류).
