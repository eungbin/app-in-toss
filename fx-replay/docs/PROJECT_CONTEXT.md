# 과거 시세 모의투자 시뮬레이터 — 프로젝트 컨텍스트

> 이 문서는 기획 대화(2026-09-05 ~ 09-07)에서 결정된 내용을 Claude Code에 인계하기 위한 것이다.

## 1. 한 줄 정의

**토스 앱인토스(Apps in Toss) 미니앱**으로 출시하는, **과거 시세 데이터를 리플레이하며 즐기는 모의투자 시뮬레이터**.
실시간 시세를 쓰는 일반 모의투자와 다르게, 과거의 특정 구간을 골라 "그때 내가 투자했다면"을 시뮬레이션한다.

## 2. 확정된 핵심 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 플랫폼 | 앱인토스 미니앱 | 설치 없이 토스 사용자 유입, 만 19세 이상 사용자 기반 |

| 목적 | **수익화가 1차 목적** | — |
| 비용 | **초기 지출 0원 원칙** | 데이터·인프라·입점 모두 무료 티어로 |
| 개발자 | 1인 (프론트엔드, React/TypeScript) | 문서 기반 개발 선호 — PRD·기능명세 먼저 |

## 3. 절대 지켜야 할 제약 (앱인토스 심사 정책)

앱인토스 오픈 정책 중 이 서비스에 직접 걸리는 조항. **위반 시 심사 반려.**

1. **금융 서비스 금지** — 대출·보험·카드·증권 등 금융 상품 관련 서비스는 인허가 여부와 무관하게 등록 불가. 실제 계좌 연동, 실제 매매, 현재가 노출 모두 금지.
2. **투자 자문·전략 안내 금지** — 특정 종목 추천, 투자 전략 제시로 투자 의사결정에 영향을 주는 서비스 불가.
   - "이 패턴이면 사라", "지금 매수 타이밍" 류 예측성 문구 **전면 금지** (유료 콘텐츠 포함)
   - 유료 콘텐츠는 반드시 **과거 사건 해설·복기** 형태여야 한다
3. **사행성 금지** — 현금·현금성 보상 지급 금지. 랭킹·배지 등 비금전 보상만 허용. 토스포인트 프로모션은 토스 측 마케팅 예산 활용 시에만.
4. **게임 재분류 리스크** — 라이프·콘텐츠로 등록했는데 게임성이 과하면 게임으로 재등록 요구 가능 → 등급분류 비용 발생. 초기 버전은 **경쟁·연승·보상 요소 최소화**, "투자 복기 콘텐츠" 톤 유지.

### UX 문구 가이드 (심사 대응)
- 첫 화면·결과 화면의 톤: "과거 차트로 배우는 투자 복기"
- 금지 톤: "수익률 랭킹 경쟁", "수익 내는 법"
- 현재 시점 시세·종목 정보는 어디에도 노출하지 않는다
- 서비스 특수성 때문에 **사전 상담(채널톡)이 붙을 확률이 높음** → 개발 전 상담 권장, 결제 항목 목록을 그대로 제시

## 4. 데이터 전략 (비용 0원)

### 핵심 제약
"수익화"와 "무료 데이터"는 충돌한다. 대부분의 무료 시세 소스는 **비상업 조건**이다.

| 소스 | 상업 이용 | 판단 |
|---|---|---|
| 공공데이터포털 금융위원회 주식 API | ✗ 공공누리 2유형(상업적 이용금지), 원천기관과 별도 계약 필요 | 사용 불가 |
| KRX 정보데이터시스템 | ✗ 상용 라이선스 유료 | 2단계로 보류 |
| Yahoo Finance(yfinance), Alpha Vantage 무료 티어 등 | ✗ 약관상 상업 이용/재배포 금지 | 사용 불가 |
| **한국은행 ECOS API** (KOSPI/KOSDAQ 지수, 환율, 금·유가 일별) | 공공누리 1유형(출처표시)으로 파악됨 — **확인 필요** | **1순위 후보** |
| 합성 시세 (GBM 등 통계 기반 랜덤 차트) | 제약 없음 | 대안 (실제 사건 리빌의 재미는 포기) |

### 결정
- **1단계(출시)**: ECOS 기반 **지수·환율·원자재 시뮬레이터**. 개별 종목 없음.
  - 부수 효과: "특정 종목 추천" 조항에서 더 멀어짐
- **2단계(수익 발생 후)**: KRX 정보이용계약 체결 후 국내 개별 종목 추가
- 종목명·날짜를 가리는 **블라인드 모드**가 핵심 게임성 (검색으로 답 찍기 방지)

### 확인 필요 ✅
- [ ] ECOS API 이용조건(공공누리 유형, 상업 이용 가능 여부) 직접 확인
- [ ] ECOS에서 제공하는 일별 지수·환율·원자재 시리즈 목록과 시작 연도 확인
- [ ] 출처표시 방식(앱 내 표기 위치) 결정

## 5. 수익 모델

우선순위 순.

1. **리워드 광고** — 하루 무료 플레이 N회 소진 후 "광고 보고 한 판 더". 회차 반복 구조와 궁합 최고. 앱인토스 인앱 광고 사용.
2. **인앱 결제 – 시나리오 팩** — 2008 금융위기, 닷컴버블, 2020 코로나 급락 등 테마별 유료 챕터(과거 사건 해설 포함). 콘텐츠 카테고리 정체성과 부합.
3. **인앱 결제 – 프리미엄(단건)** — 광고 제거 + 기간·자산 확장 + 복기 리포트 저장. 구독보다 단건 결제가 심사·수수료 면에서 단순.
4. 토스포인트 프로모션 — 유입용으로만. 자체 현금 보상 절대 금지.

비용 구조: 입점·심사 무료, 광고·결제는 매출 발생 시 수수료(레비뉴 셰어) → 선지출 없음. 정산을 위해 **개인사업자 등록** 필요(무료).

## 6. 인프라 (비용 0원)

과거 데이터는 불변이므로 **서버 불필요**.

- 일별 데이터를 시나리오/기간 단위 **JSON 청크로 정적 번들링**
- 호스팅: Vercel 또는 Cloudflare Pages 무료 티어
- 유저 진행 상태: 앱인토스 네이티브 저장소
- 랭킹 등 공유 상태가 필요해지면: Supabase 무료 티어
- 프론트: React + TypeScript (개발자 주력 스택), 앱인토스 SDK

## 7. 제품 설계 포인트

- **블라인드 모드**: 자산명·날짜 마스킹, 차트만 노출. 플레이 종료 후 리빌.
- **시나리오 챕터**: 실제 역사적 사건 구간 (금융위기, 팬데믹, 버블 등). 재방문 훅 + 유료화 단위.
- **시간 압축 리플레이**: 1일 = 수 초 단위로 진행, 매수/매도/관망 선택.
- **복기 리포트**: 결과 화면에 "그때 실제로 어떤 일이 있었나" 해설 + 내 판단 복기. 교육/콘텐츠 톤의 핵심.
- **게이미피케이션 최소화**: 배지 정도. 랭킹·연승·경쟁은 초기 버전에서 제외 또는 비노출.
