# rent-calc ("월세 이거 맞아?") 상태

파생할 수 있는 것(광고 ID 단계, deploy 스크립트, 가드, 마지막 커밋)은 여기 적지 않는다.
루트에서 `npm run status` 로 본다. 이 파일에는 **파일에서 읽어낼 수 없는 것만** 적는다 —
콘솔 등록·심사·정산처럼 앱인토스 쪽에만 있는 사실이다.

- **단계**: **앱 정보 검토 반려 — 채널톡 답신 대기** (2026-09-09)
- 갱신: 2026-09-09

## 앱 정보 검토 반려 (2026-09-09)

**받은 회신 원문**

> 입력해주신 앱 정보만으로는 서비스 확인 및 심사가 어렵습니다. 채널톡으로 실제 제공 예정인
> 서비스의 구체적인 내용(핵심 기능·이용 방식 등)을 전달해 주세요.

**원인으로 보는 것.** 콘솔 상세 설명(첫 판 426자)이 "무엇을 판정한다 / 무엇이 아니다"에
지면을 많이 쓰고 **이용 방식이 없었다.** 승인받은 net-pay(475자)·photo-standard(492자)는
콘솔 가이드가 요구하는 **"서비스 접속 → 행동 → 결과"** 흐름으로 쓰여 있다. 그 차이가
"서비스 확인이 어렵다"는 회신으로 돌아온 것으로 본다.

**전제가 바뀌었다.** 이 앱은 "사전 상담 없이 진행"으로 정해 두었고 세 앱이 그렇게 승인받았다.
그러나 **앱 정보 검토에서 채널톡 전달을 요구받을 수 있다.** 사전 상담이 선택이라는 판단은
유지하되, 채널톡 설명 문구는 미리 준비해 두는 것이 맞다 —
[SUBMISSION 2장](docs/SUBMISSION.md)에 답신을 두었고 루트 [PLAYBOOK](../docs/PLAYBOOK.md) 6장에 적었다.

**대응** (세션이 준비한 것, 2026-09-09)
- 상세 설명을 접속 → 행동 → 결과 흐름으로 재작성 — 426자 → **495자** ([SUBMISSION 1-3](docs/SUBMISSION.md))
- 채널톡 답신 작성 — 핵심 기능 5개, 실제 예시 숫자, 계산 근거 법령, 수익 모델,
  하지 않는 것 5항목 ([SUBMISSION 2장](docs/SUBMISSION.md))

**사용자가 할 일**: 채널톡 답신 발송 + 콘솔 상세 설명을 495자 판으로 교체.

## 콘솔 (미확인 — 사용자가 채워 넣는다)

세션이 콘솔에 접근하지 않았다. 아래는 등록했다고 들은 것만 적고 나머지는 비워 둔다.

| 항목 | 상태 |
|---|---|
| miniAppId | **미확인** |
| appName | 폴더명과 같게 `rent-calc` 를 쓴다(등록값 확인 필요) |
| 앱 이름 | 국문 **월세 이거 맞아?** / 영문 **RentCheck** — 물음표 허용 여부 확인 필요 |
| 부제 | 제안받은 월세, 법정 상한 안인지 판정 |
| 카테고리 | 생활 > 편의 (소분류는 콘솔에서. work-journal 은 **도구** 를 골랐다) |
| 검색 키워드 | 10개 준비됨 ([SUBMISSION 1-4](docs/SUBMISSION.md)). 실제 등록값 확인 필요 |
| 고객문의 이메일 | 미입력 — `.env` `VITE_SUPPORT_EMAIL` 과 같은 값이어야 한다 |
| 로고 | 초안 `assets/logo-600.png` (체크 + 계약서 밑줄). 등록 여부 확인 필요 |
| 스크린샷 | **0장** (세로 636×1048 최소 3장). 구성안은 [SUBMISSION 1-5](docs/SUBMISSION.md) |
| 광고 그룹 | **없음**. 리워드·배너 2개 필요 |
| 번들 | **업로드 없음**. `deploy` 스크립트도 아직 없다 |
| 심사 | 앱 정보 검토 **반려**(위). 번들 검토 요청은 한 적 없다 |
| 약관 | 등록하지 않는다 — 토스 로그인을 쓰지 않는다(net-pay·photo-standard 도 등록 없이 승인) |
