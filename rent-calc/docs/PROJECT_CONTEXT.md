# "월세 이거 맞아?" — 전월세 계산기 프로젝트 컨텍스트

> 이 문서는 기획 대화(2026-09-08)에서 결정된 내용을 다음 단계(PRD)로 인계하기 위한 것이다.
> 2장의 결정은 확정이므로 재논의하지 않는다. "확인 필요" 표시된 항목만 열려 있다.
> 세 번째 앱이다. 선행 앱: [fx-replay](../../fx-replay/docs/PROJECT_CONTEXT.md)(라이프·콘텐츠), [net-pay](../../net-pay/docs/PRD.md)(유틸리티).

---

## 1. 한 줄 정의

**토스 앱인토스 미니앱**으로 출시하는 **전월세 계산기 "월세 이거 맞아?"**(폴더 `rent-calc`, 콘솔 영문명 `RentCheck`). 집주인이 내민 월세·보증금 제안이 **법정 상한을 넘는지 한 줄로 판정**하는 것이 메인 훅이고, 전세↔월세 환산·중개보수 상한·임대차 신고 대상 판정은 표준 기능으로 제공한다.

## 2. 확정된 핵심 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 아이디어 | 전월세 계산기 (후보 4개 비교에서 선정: 전월세 / 육아휴직 급여 / 연차 연휴 최적화 / 전기요금 누진) | 데이터 파이프라인 둘(법령 별표 파서, ECOS 기준금리)이 이미 저장소에 있어 출시 속도가 가장 빠름. 상시 수요. 계산 내용이 전부 확정된 법령 수치 |
| 차별점 (메인 훅) | **판정** — "이 제안, 법정 상한 넘었나?" 현재 조건과 제안 조건을 넣으면 초과 여부·초과액·법정 최대치를 한 화면에 | 기존 계산기는 전부 "환산"만 한다. 세입자가 실제로 궁금한 건 숫자가 아니라 "이거 받아도 되나"다 |
| 차별점 (공유 카드 요소) | **시간축** — 같은 보증금을 월세로 돌릴 때 법정 상한 월세가 기준금리 변동에 따라 연도별로 어떻게 달랐나 | fx-replay·net-pay와 같은 "과거 → 지금" DNA. 기준금리 시계열은 fx-replay 파이프라인 그대로 |
| 나머지 기능 | 표준 계산기 수준 (전세↔월세 환산, 중개보수 상한, 임대차 신고 대상·기한) | 차별점 하나, 출시 속도 우선 (net-pay와 같은 원칙) |
| 수익 모델 | **v1.0 광고 전용 (리워드 + 배너), 서버 0** | IAP는 토스 로그인 + mTLS 서버가 필요하다 ([[apps-in-toss-iap-needs-server]]) |
| 카테고리 | **유틸리티** (재테크·금융 회피) | net-pay와 같은 판단. 중분류는 확인 필요 (6장) |
| 비용 | 초기 지출 0원 | 데이터는 법령·ECOS 번들, 호스팅은 앱인토스 번들 업로드 |
| 공용 코드 | `@ait/kit` 사용. 광고·저장·네비·공유·환경을 앱 안에 다시 만들지 않는다 | [SHARED_PACKAGE.md](../../docs/SHARED_PACKAGE.md) |
| 착수 시점 | **net-pay 심사 제출 이후 개발 착수.** 그 전까지는 문서 단계만 | net-pay가 fx-replay 제출 뒤에 착수한 것과 같은 순서 |
| 전략 | 포트폴리오 — net-pay와 진입점 상호 링크 ("실수령 대비 주거비 비율") | 앱 1개의 광고 수익은 작다 |

## 3. 계산 규칙 (법령 원문 확인 완료, 2026-09-08)

전부 확정된 법령 수치다. 개발 시 골든 테스트의 기대값은 net-pay와 같이 **구현 코드를 거치지 않는 경로**(원문 숫자 리터럴 산술)로 만든다.

### 3-1. 보증금 → 월세 전환 상한 (주택임대차보호법 제7조의2, 시행령 제9조)
- 전환되는 보증금 × **두 비율 중 낮은 것** ÷ 12 = 월세 상한
  - ① 연 **10%** (시행령 제9조 제1항 "연 1할")
  - ② **한국은행 공시 기준금리 + 연 2%** (시행령 제9조 제2항)
- 기준금리는 **전환 시점**에 공시된 값. 2026-08-27 인상으로 **3.00%** (웹 검색 결과 — 빌드 시 ECOS 722Y001로 확정) → 현재 상한은 연 5%.
- **월세 → 보증금 전환에는 상한이 없다.** 앱은 방향에 따라 판정을 켜고 끈다.

### 3-2. 갱신·존속 중 증액 상한 (주택임대차보호법 제7조, 제6조의3 제3항)
- 증액 청구는 약정 차임·보증금의 **20분의 1(5%)** 을 초과할 수 없다.
- 계약 또는 직전 증액 후 **1년 이내** 재증액 불가.
- 광역 지자체가 **조례로 상한을 달리(더 낮게) 정할 수 있다** → 확인 필요 (6장).

### 3-3. 적용 범위 — 가장 중요한 정확성 포인트
- 3-1·3-2 상한은 **계약 존속 중 변경**과 **계약갱신요구권 행사에 따른 갱신**에 적용된다.
- **신규 계약(다른 집으로 이사, 갱신요구권 없이 새로 맺는 계약)에는 상한이 없다.**
- 따라서 첫 화면은 반드시 "갱신·기간 중 변경 / 신규 계약"을 먼저 고르게 하고, 신규 계약에서는 판정을 끄고 **환산 참고치만** 보여준다. 이걸 흐리면 "법 위반"이라는 잘못된 판정을 내보내게 되고 심사·민원 리스크가 된다.

### 3-4. 중개보수 상한 (공인중개사법 시행규칙 제20조, 별표 1 — 2021-10-19 신설)
- 거래금액 × 상한요율, 단 한도액 이내. 요율은 **상한**이고 실제 금액은 협의. 부가세 별도.
- 임대차 거래금액 환산: **보증금 + 월세 × 100**. 그 값이 5천만 원 미만이면 **보증금 + 월세 × 70**으로 다시 계산.

| 구분 | 거래금액 | 상한요율 | 한도액 |
|---|---|---|---|
| 임대차 | 5천만 미만 | 0.5% | 20만 |
| 임대차 | 5천만~1억 미만 | 0.4% | 30만 |
| 임대차 | 1억~6억 미만 | 0.3% | — |
| 임대차 | 6억~12억 미만 | 0.4% | — |
| 임대차 | 12억~15억 미만 | 0.5% | — |
| 임대차 | 15억 이상 | 0.6% | — |
| 매매·교환 | 5천만 미만 | 0.6% | 25만 |
| 매매·교환 | 5천만~2억 미만 | 0.5% | 80만 |
| 매매·교환 | 2억~9억 미만 | 0.4% | — |
| 매매·교환 | 9억~12억 미만 | 0.5% | — |
| 매매·교환 | 12억~15억 미만 | 0.6% | — |
| 매매·교환 | 15억 이상 | 0.7% | — |

- 원문은 국가법령정보센터 별표 평문 다운로드로 **자동 수집 확인 완료**(법령 lsiSeq 288753, 별표 bylSeq 18379871, 2.6KB). net-pay `scripts/fetch-tax-table.ts` 흐름 그대로.
- "주택"은 건축법상 주택 전부(단독·다가구·다중·다세대·연립·아파트·도시형생활주택). 오피스텔만 별도 요율(제20조 제4항) → v1.0 포함(6장). 지자체 조례가 별표 범위 안에서 요율을 정한다 → 확인 필요 (6장).

### 3-5. 임대차 신고 대상 (부동산 거래신고 등에 관한 법률)
- **보증금 6천만 원 초과 또는 월세 30만 원 초과** (둘 중 하나만 넘어도 대상). 계약 후 **30일 이내**.
- 과태료: 지연·미신고 2만~30만 원, 허위 신고 최대 100만 원. 2025-06-01 이후 계약부터 부과.
- 신고 대상 지역(군 지역 제외 등)은 확인 필요 (6장). v1.0은 "대상 여부 + 기한"만 알려주고 지역 판정은 하지 않는 안이 유력.

| 데이터 | 출처 | 라이선스 | 수집 방법 | 갱신 |

| 기준금리 시계열 | ECOS 722Y001 (한국은행 작성) | 출처 표시로 상업 이용 가능 ([[ecos-license-by-source-org]]) | fx-replay `scripts/fetch-ecos.ts` 재사용. **컷오프 없음** — 최신값이 필요하다 (fx-replay의 12개월 컷오프는 투자 자문 방어용이라 여기엔 해당 없음) | 금통위 결정 시(연 수 회). 번들 최신값 + **사용자가 직접 수정 가능한 기준금리 입력칸** + "YYYY-MM-DD 공시 기준" 각주로 앱 갱신 없이 버틴다 |

번들 크기: 기준금리 일별 30년치도 100KB 미만. 전부 정적 포함, 서버 0.

## 5. 심사 대응 원칙 (설계 제약)

1. **금융 상품과의 거리** — 전세자금대출·보증보험·월세 카드납 어떤 상품도 노출·추천·링크하지 않는다. "이 보증금이면 대출 한도는" 류 파생 기능 금지. 토스 자체 부동산·대출 서비스 영역으로 확장하지 않는다.
2. **법률 자문이 아니다** — 모든 결과는 "법령 수치에 따른 참고 판정"이며 개별 계약·조례·특약에 따라 다를 수 있음을 결과 화면마다 명시. "위반"이라는 단정 대신 "법정 상한 초과" 표현. 분쟁 시 연결 창구는 공적 기관(임대차분쟁조정위원회) 링크만.
3. **부동산 중개가 아니다** — 매물·시세·지역 정보 없음. 중개보수는 "상한 계산"만.
4. **개인정보 0** — 입력값은 기기 안에서만 계산, 저장은 앱인토스 Storage. 서버 없음.
5. **토스 네비 규칙** — 자체 헤더·뒤로가기 금지, backEvent 라우팅, 첫 화면 Screen.close ([[fx-replay-decisions]]).
6. **사전 상담** — 카테고리 확인 겸 채널톡 사전 상담. net-pay SUBMISSION.md의 메시지 템플릿 재사용.

- [ ] **카테고리 중분류.** (조사 항목, 사전 상담) 콘솔 공개 문서에 비게임 카테고리 전체 목록이 없다. 유틸리티 대분류 아래 부동산·주거 중분류가 있는지, 있다면 심사 기준이 다른지 사전 상담에서 확인. 없으면 유틸리티 > 계산기 류로 제출.
- [x] **조례 편차** — 2026-09-08 조사: 5% 상한을 조례로 낮춘 시·도는 확인되지 않음(생활법령정보 "별도 조례 없으면 5%"). 서울시 주택 중개보수 조례 별표 1은 시행규칙 별표 1과 동일. 타 시·도 전수 확인은 W1(PRD O-4). 앱은 "조례에 따라 다를 수 있어요" 각주로 처리.
- [x] **오피스텔** — 주거용 오피스텔 중개보수 요율(제20조 제4항, 85㎡ 이하·부엌·화장실 조건 시 매매 0.5%·임대차 0.4%, 그 외 0.9% 협의)을 **v1.0에 포함**, 중개보수 화면에 "오피스텔인가요?" 토글 (2026-09-08 확정). 조건 세부는 개발 시 원문 확인. 판정 기능(5%·전환율)은 주임법 적용 대상이라 오피스텔에도 원래 적용된다.
- [x] **매매 중개보수** — v1.0 임대차만, 매매는 v1.1 (2026-09-08 확정).
- [x] **신고 대상 지역 판정** — v1.0은 금액 기준만 판정 + "지역에 따라 제외될 수 있음" 각주 (2026-09-08 확정).
- [x] **광고 게이트** — 판정·환산·중개보수·신고 판정 전부 무료, 시간축 카드와 저장 초과만 게이트, 광고 1회 = 전체 해제 (2026-09-08 확정, net-pay 원칙 동일).
- [x] **시간축 범위** — 2021~2026 매년 1월 1일 기준 6개 점 + 최신값 (2026-09-08 확정, net-pay와 같은 연도 범위).
- [ ] **기준금리 최신값 확정.** (조사 항목, 빌드 시 자동) 빌드 시 ECOS 722Y001에서 받아 3.00%(2026-08-27)가 맞는지 확인.
