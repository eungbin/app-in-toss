## 1. 콘솔 등록 입력값

그대로 복사해 넣을 수 있게 정리했다.

### 1-1. 기본 정보

| 필드 | 값 | 비고 |
|---|---|---|
| 앱 유형 | **비게임** | |
| 카테고리 | **생활 > 편의** | 1-2 참조 |
| 앱 이름(국문) | **월세 이거 맞아?** | 물음표가 허용되는지 콘솔 입력 시 확인. 막히면 "월세 이거 맞아" |
| 앱 이름(영문) | **RentCheck** | 15자 이내 명사형 ✓ (9자) |
| 부제 | **제안받은 월세, 법정 상한 안인지 판정** | |
| 고객문의 이메일 | `.env` 의 `VITE_SUPPORT_EMAIL` 과 **같은 값** | 빌드 가드가 비어 있으면 막는다 |
| 앱 로고 | 600×600 PNG, 정사각형, 둥근 모서리 없음 | `assets/logo-600.png` (**초안** — 체크 + 계약서 밑줄, `npx tsx scripts/gen-logo.ts` 로 재생성) |
| 스크린샷 | 세로 636×1048 PNG. 선택 사항 | 1-4 구성안 |

### 1-2. 카테고리 — 생활 > 편의

콘솔은 비게임 앱을 **대분류 → 중분류 → 소분류**로 받는다. 대분류는 '생활' 하나뿐이고
중분류는 복수 선택이며, 소분류는 일부 중분류에만 있고 콘솔에서만 목록을 볼 수 있다.

**중분류 15개**(2026-09-08 콘솔 확인): 음식 · 교육 · 건강 · 교통 · 공공 · 소셜 · **편의** ·
쇼핑 · AI · 비즈니스 · 콘텐츠 · 여행 · 일상 · **정보** · 재테크

| 중분류 | 판단 |
|---|---|
| **편의** | **1순위.** 생활 편의 도구 자리. 계산기·판정 도구가 가장 자연스럽다 |
| **정보** | **2순위.** 법령 수치로 계산해 알려주는 성격과 맞다 |
| 공공 | 법령 기반이라 후보이나 공공기관 서비스로 오해될 수 있다. "국토교통부가 제공·인증한 서비스가 아닙니다"를 넣는 앱이 공공 카테고리에 있으면 모순이다 |
| 일상 | 가능하나 범위가 넓어 발견성이 떨어진다 |
| 재테크 | **피한다.** 아래 |

**부동산 중분류는 없다.** PRD 오픈 이슈 O-2는 이렇게 닫혔다 — 별도 부동산 카테고리가
없으므로 심사 기준이 달라질 여지도 없다.

**재테크를 피하는 이유**: 발견성만 보면 유리하다. 그러나 오픈 정책이 "대출·보험·카드·증권 등
금융 상품 관련 서비스"를 금지하는데 카테고리가 재테크면 심사자가 그 렌즈로 본다. 이 앱은
전세자금대출·보증보험을 일부러 배제했는데도 설명할 일이 생긴다(PRD 원칙 A2).

### 1-3. 상세 설명 (콘솔 "상세 설명" 필드)

> "월세 이거 맞아?"는 주택임대차보호법·공인중개사법과 한국은행 기준금리를 바탕으로 전월세 조건을 계산하는 도구입니다.
>
> 사용자는 (1) 갱신이나 계약 기간 중 제안받은 보증금·월세가 법정 상한(증액 5%, 보증금→월세 전환율) 안인지 확인하고, (2) 전세와 월세를 서로 환산하고, (3) 중개보수 상한과 임대차 신고 대상 여부를 확인할 수 있습니다. 같은 보증금의 전환 상한 월세가 연도별 기준금리에 따라 어떻게 달랐는지도 비교할 수 있습니다.
>
> 신규 계약에는 법정 상한이 적용되지 않으므로, 첫 화면에서 "갱신·기간 중 변경"과 "신규 계약"을 구분해 선택하도록 했습니다. 신규 계약에서는 판정 없이 환산 참고치만 보여 줍니다.
>
> 본 서비스는 금융 상품을 소개·연결하지 않으며, 매물·시세 정보를 제공하지 않고, 모든 결과는 참고용 계산값입니다. 입력값은 서버로 전송되지 않고 기기 안에서만 처리됩니다. 사용자 간 경쟁, 현금성 보상, 확률형 요소가 없습니다.
>
> 데이터 출처: 주택임대차보호법·시행령, 공인중개사법 시행규칙 별표 1·2, 부동산 거래신고 등에 관한 법률(국가법령정보센터), 한국은행 경제통계시스템(ECOS) 722Y001 한국은행 기준금리.

**수익 항목**: 인앱 광고 — 보상형(연도별 전환 상한 비교·저장 확장 1일 열기), 배너(홈·환산·중개보수·신고·저장 목록 하단). 토스 애즈 SSP만 사용. 인앱결제 없음(v1.0).

### 1-4. 스크린샷 구성안 (5장)

| # | 화면 | 보여 줄 것 | 입력 예 |
|---|---|---|---|
| 1 | S01 판정(초과) | 첫 화면 = 판정. 헤드라인·인상률·법정 최대치 | 지금 1억/0 → 제안 5,000만/25만 |
| 2 | S02 판정 상세 | 산식 표, 법정 최대치, 기준·면책 | 같은 입력 |
| 3 | S03 시간축 | 막대 7개, 연도별 표, 서술형 문장 | 보증금 5,000만 |
| 4 | S06 중개보수 | 오피스텔 토글, ×70 재계산 각주 | 1,000만/30만 |
| 5 | S07 임대차 신고 | 대상 여부·이유·기한 | 7,000만/35만, 계약일 |

**주의**
- 개발 서버(`npm run dev`)가 아니라 QR 테스트 빌드에서 촬영한다.
- 기준금리 각주가 `(YYYY-MM-DD 한국은행 공시)`로 나오는지 확인한다. `(직접 입력)`이 보이면
  설정에서 번들값으로 되돌린 뒤 촬영한다.
- 저장·해제 상태가 남아 있으면 설정에서 전체 삭제 후 촬영한다.

## 3. 남은 작업 (의존 순서)

**1~3은 사용자 작업이다.** 정산·광고은 사업자 계정 건이라 세션이 대신할 수 없다.

1. **광고 그룹 생성** — 콘솔 광고 그룹 관리에서 **2개**(리워드·배너). 정산 정보 검토를
   통과해야 메뉴가 열리고, 생성 즉시 ID가 나오지만 구글 등록까지 최대 2시간 걸린다.
   절차와 매월 승인 기한은 [../../docs/SETTLEMENT.md](../../docs/SETTLEMENT.md).

   | 광고 유형 | 그룹 이름(안) | 보상 이름 | 수량 |
   |---|---|---|---|
   | 리워드 | `rentcheck-rewarded-gate` | 오늘 하루 열기 | 1 |
   | 배너 | `rentcheck-banner-bottom` | — | — |

2. **`.env` 채우기** — `VITE_AD_REWARDED_ID`, `VITE_AD_BANNER_ID`, `VITE_SUPPORT_EMAIL`.
   이메일은 콘솔 등록값과 같아야 한다. 현재 `npm run build` 는 이메일이 없어 막혀 있다.
3. **로고 확정** — 현재는 초안(체크 + 계약서 밑줄, 브랜드 블루 #3182F6).
   `scripts/gen-logo.ts` 좌표를 고치거나 별도 제작 PNG로 교체한다.
4. **QR 테스트** — `npm run build` (테스트 광고 ID 상태) → 실기기에서 2-2 항목 13개.
5. **스크린샷 5장** — 1-4 구성안. QR 테스트와 함께.
6. **출시 빌드** — `npm run build:release`. 실 광고 ID가 없으면 막힌다.
7. **콘솔 앱 정보 입력** (1-1 표) → **심사 제출**. 영업일 3일, 카테고리에 따라 7일 이상.

**검증에 남은 것** (출시를 막지는 않는다)
- 5% 증액 상한을 조례로 낮춘 시·도가 있는지 자치법규정보시스템 전수 확인
  ([FACT_CHECK 4-2](FACT_CHECK.md)). 현재까지 확인된 사례 없음 → 앱은 각주로 처리
- 오피스텔 "그 외" 0.9% 협의 케이스는 공공 계산기에 옵션이 없어 리터럴만 대조

## 4. 연간 유지보수

| 시점 | 작업 |
|---|---|
| 금통위 결정 후 | `npm run data:fetch` → `check:data` → 재제출. 기준금리가 바뀌면 전환율 상한이 바뀐다 |
| 90일 경과 | 화면에 "기준금리가 바뀌었을 수 있어요" 안내가 뜬다(사용자가 직접 입력 가능) |
| 180일 경과 | 프로덕션 빌드가 막힌다 |
| 법령 개정 시 | 중개보수 별표는 `data:fetch` → `data:build`. 조문 상수는 `legal.json` 수동 수정 후 `legal.test.ts` 통과 확인 |

기준금리는 앱 갱신 없이도 사용자가 설정에서 직접 넣을 수 있다. 갱신이 늦어도 앱이 틀린
값을 강요하지 않는 구조다(DT-5).
