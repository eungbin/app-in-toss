## 1. 서비스 정의

### 1-1. 한 줄 정의
"받고 싶은 세후 월급"을 입력하면 그에 필요한 **연봉(세전)을 역산**해 주고, 그 연봉이 5년 전이었다면 실수령이 얼마였는지 **시간축으로 비교**해 주는 월급 계산기. 정방향 계산(연봉 → 실수령), 퇴직금, 연차수당은 표준 기능으로 제공한다.

### 1-2. 무엇이 아닌가 (심사 대응의 출발점)
- 금융 상품을 팔거나 연결하는 앱이 아니다. 대출·보험·카드·증권 어떤 상품도 노출·추천·링크하지 않는다.
- 세무 대리·세무 상담이 아니다. 모든 결과는 **국세청 간이세액표와 공단 요율표에 따른 참고 수치**이며, 실제 원천징수액은 회사·개인 사정에 따라 다를 수 있음을 결과 화면마다 명시한다.
- 개인정보를 수집하지 않는다. 연봉·가족 수 등 입력값은 **기기 안에서만 계산**되고 서버로 전송되지 않는다(서버 자체가 없다). 저장은 앱인토스 Storage에만 한다.
- 게임이 아니다. 랭킹·보상·확률 요소가 없다.

### 1-3. 왜 이 조합인가
1. **수요**: "연봉 실수령액"은 매년 1월(연봉 협상), 3월(간이세액표 개정), 이직 시즌에 반복 검색되는 국내 최대 규모 금융 계산기 키워드다.
2. **문맥**: 토스 사용자는 급여 통장 잔액을 보다가 들어온다. "내 실수령이 X인데 연봉은 얼마인 거지 / 얼마를 불러야 Y가 되지"는 실수령이 출발점이다. 역산이 자연스러운 첫 화면이 된다.
3. **비어 있는 자리**: 앱스토어에는 실수령 계산기가 많지만(이직 시뮬레이터를 갖춘 것도 있음) **역산과 시간축을 메인으로 세운 것은 없다.** 앱인토스 안에는 카테고리 자체가 비어 있다.
4. **라이선스**: 근로소득 간이세액표는 공공데이터포털에 **"이용허락범위 제한 없음"**으로 공개되어 있다(국세청, 2026-02-23 수정 확인). 4대보험 요율·상하한은 공단·복지부 고시로 공개된 수치다. ECOS처럼 작성기관별 조건을 따질 필요가 없다.
5. **데이터 크기**: 간이세액표는 월급 구간 약 1,000행 × 가족 수 11열. JSON 50KB 내외. 요율표는 수십 행. 전부 번들 포함.

### 1-4. 타깃 사용자
- 토스 사용자(만 19세 이상) 중 급여 근로자. 특히 연봉 협상·이직 제안을 앞둔 20~30대.
- 사용 시간 1~3분. 한 번에 끝나는 도구형 사용.
- 페르소나: "이직 제안 연봉이 세후로 얼마인지 바로 알고 싶은 사람" / "월 실수령 400을 목표로 연봉 협상 숫자를 정하려는 사람" / "5년 동안 연봉은 올랐는데 통장은 왜 그대로인지 궁금한 사람".

### 1-5. 성공 지표 (출시 후 90일)

계산기는 리텐션이 낮은 도구형 앱이므로 fx-replay와 다른 지표를 본다.

| 지표 | 목표 | 측정 |
|---|---|---|
| 세션당 계산 수 | 2.0회 이상 | 자체 이벤트 `calc_done` |
| 역산 사용 비율 (전체 계산 중) | 40% 이상 | `calc_done{mode=reverse}` / 전체 |
| 리워드 광고 시청률 (게이트 진입자 중) | 35% | `userEarnedReward` / 게이트 노출 |
| 공유 카드 생성률 (결과 화면 도달자 중) | 8% | `share_card_created` |
| 30일 재방문율 | 15% | 앱인토스 분석 대시보드 |
| 심사 | 1차 제출 반려 0건 | 콘솔 반려 사유 |

## 2. 심사 대응 원칙 (설계 제약)

앱인토스 서비스 오픈 정책에서 이 서비스에 걸릴 수 있는 조항과 설계 수준의 대응.

### 2-1. 원칙 A — 금융 상품과의 거리
정책: "대출·보험·카드·증권 등 금융 상품 관련 서비스는 … 등록할 수 없어요."

| 규칙 | 구현 |
|---|---|
| A1. 상품 노출 0 | 대출·적금·보험·카드 어떤 상품명·상품 유형도 화면에 없다. "이 연봉이면 대출 한도는" 류 파생 기능 금지. |
| A2. 카테고리 | 유틸리티·도구 계열로 등록. 재테크·금융 계열은 금융 조항 렌즈로 검토될 가능성이 높아 피한다(fx-replay와 같은 판단). 콘솔은 대·중·소 3단이고 중분류를 복수로 고른다 |
| A3. 외부 링크 | 국세청·공단 출처 링크와 고객문의 이메일만. 토스 금융 서비스 딥링크 없음. |
| A4. 토스 자체 기능과 중복 회피 | 토스가 직접 제공하는 대출 비교·자산 조회 영역으로 확장하지 않는다. |

### 2-2. 원칙 B — 세무 자문이 아닌 참고 계산
정책 직접 조항은 없으나 세무사법(세무 대리 자격)과 심사 시 "정확성 책임" 질의에 대비.

| 규칙 | 구현 |
|---|---|
| B1. 면책 문구 고정 | 모든 결과 화면 하단: "간이세액표·공단 요율 기준 참고용 계산입니다. 실제 공제액은 회사·개인 상황에 따라 다를 수 있어요." |
| B2. 기준일 표기 | 결과마다 적용 기준 표기: "2026-03-01 시행 간이세액표 · 2026년 4대보험 요율". |
| B3. 단정·권고 금지 | "얼마를 불러라", "이직하라", "이 정도가 적정 연봉" 같은 권고·평가 문구 없음. 수치와 산식 근거만 제시. fx-replay의 `lint-copy.ts` 금지어 사전을 이 서비스용으로 교체해 빌드 시 차단. |
| B4. 연말정산 미포함 명시 | "연말정산 결과(환급·추가 납부)는 반영되지 않습니다"를 상세 내역에 표기. |

### 2-3. 원칙 C — 개인정보 최소화
| 규칙 | 구현 |
|---|---|
| C1. 서버 없음 | 입력값은 기기 내 계산. 네트워크 호출은 앱인토스 SDK(광고)만. |
| C2. 저장 최소 | 저장 항목은 사용자가 명시적으로 "저장"한 시나리오만. 앱인토스 Storage API 사용. 삭제 버튼 제공. |
| C3. 식별 | `User.getAnonymousKey`만. 토스 로그인 없음(v1.0). |
| C4. 문구 | 첫 화면 하단 한 줄: "입력한 금액은 이 기기 안에서만 계산돼요." — 차별점이자 심사 설명 문구. |

### 2-4. 원칙 D — 광고 보상은 기능 잠금 해제만
| 규칙 | 구현 |
|---|---|
| D1. 보상 종류 | 리워드 광고 보상은 "프리미엄 기능 오늘 하루 열기" 하나. 포인트·현금성 보상 없음. |
| D2. 지급 조건 | `userEarnedReward` 이벤트에서만 지급. `dismissed`만으로 지급 금지. |
| D3. 노출 위치 | 배너는 홈·결과 하단(스크롤 화면). 입력 중·로딩·바텀시트에 광고 없음. 진입 즉시 바텀시트 자동 오픈 금지. |

### 2-5. 콘솔 상세 설명 문구 (초안)

> **서비스 설명**
> "세후로 말해줘"는 국세청이 공개한 근로소득 간이세액표와 4대 사회보험 요율을 바탕으로 월급 실수령액을 계산하는 도구입니다.
> 사용자는 (1) 받고 싶은 세후 월급을 입력해 필요한 연봉을 역으로 계산하거나, (2) 연봉을 입력해 월 실수령액과 공제 내역을 확인하고, (3) 같은 연봉이 과거 연도였다면 실수령이 얼마였는지 비교할 수 있습니다. 퇴직금과 미사용 연차수당 계산기를 함께 제공합니다.
> 본 서비스는 금융 상품을 소개·연결하지 않으며, 모든 결과는 참고용 계산값입니다. 입력값은 서버로 전송되지 않고 기기 안에서만 처리됩니다. 사용자 간 경쟁, 현금성 보상, 확률형 요소가 없습니다.
> 데이터 출처: 국세청 근로소득 간이세액표(공공데이터포털, 이용허락범위 제한 없음), 국민연금공단·국민건강보험공단·고용노동부 고시 요율.

> **수익 항목**: 인앱 광고 — 보상형(프리미엄 기능 1일 열기), 배너(홈·결과 화면 하단). 토스 애즈 SSP만 사용. 인앱결제 없음(v1.0).

## 3. 핵심 사용자 흐름

```
홈(=역산 입력) ─┬─ [세후 월급 입력] ──▶ 역산 결과(필요 연봉, 월 공제 내역)
                │                          ├─ 시간축 카드 "이 연봉, 5년 전이었다면"  ◀ 게이트
                │                          ├─ 협상 카드 만들기(공유)                 (무료)
                │                          └─ 시나리오 저장 / 정방향으로 전환
                ├─ [연봉으로 계산] 탭 ──▶ 정방향 결과(월 실수령, 항목별 공제)
                ├─ [퇴직금] ──▶ 입력(입사일·퇴사일·최근 3개월 임금) ─ 결과
                ├─ [연차수당] ──▶ 입력(월 통상임금·잔여 연차) ─ 결과
                ├─ [저장한 시나리오] ─ 목록 ─ 비교 보기(2개 병렬)                 ◀ 게이트
                └─ [설정] 데이터 출처·기준일, 저장 데이터 삭제, 고객문의
```

### 3-1. 첫 화면 = 역산 (핵심)
1. 화면 상단 큰 입력창 하나: **"세후로 월 ___ 만 원 받고 싶어요"**. 기본값은 비어 있고, 플레이스홀더로 예시(300).
2. 그 아래 접힌 옵션: 부양가족 수(본인 포함, 기본 1), 20세 이하 자녀 수(기본 0), 비과세 식대(기본 월 20만 원 포함, 토글), 상여 포함 여부(기본: 연봉 ÷ 12 균등).
3. 입력 즉시(디바운스 300ms) 결과 카드가 아래에 나타난다: **"연봉 약 4,470만 원이 필요해요"** + 월 공제 합계 + 항목별 내역(국민연금·건강·장기요양·고용·소득세·지방소득세).
4. 결과 카드 아래에 두 줄 스위치: "지금 연봉이 있다면 → 연봉으로 계산" (정방향 전환). 정방향에서는 같은 카드가 "월 실수령 ___원"으로 바뀐다.
5. 상세 내역 하단에 기준일·면책 문구(원칙 B1·B2) 고정.

### 3-2. 시간축 카드 (차별점 B, 게이트)
- 결과 카드 아래 "이 연봉, 5년 전이었다면" 카드. 잠금 상태에서는 헤드라인만 보이고 수치는 흐림 처리.
- 열면: 연도별(기준 연도 −5 … 현재) 같은 세전 연봉의 월 실수령 막대 차트 + "5년 동안 매달 ○○원을 더 떼이게 됐어요" 한 문장(서술형, 평가 없음). 각 연도의 요율 변화(국민연금 9.0 → 9.5%, 건강보험 6.x → 7.19% 등)를 하단 표로.
- v1.0 범위: 2021~2026 5년. **4대보험은 연도별 실제 요율·상하한**(각 연도 하반기 시행값), 소득세는 확보한 연도의 간이세액표만 적용하고 미확보 연도는 "소득세는 현행 세액표 기준" 각주. 확보 연도는 5-1 참조.

### 3-3. 협상 카드 (무료)
- 한 장 이미지: "세후 월 300만 원 = 연봉 약 4,470만 원 · 2026년 기준 · 월 공제 약 ○○만 원". 금액 노출 여부는 사용자가 토글(연봉 숨기고 실수령만 보이기 가능).
- `getTossShareLink`로 공유. 딥링크 진입 시 같은 입력값이 채워진 상태로 열린다(`intoss://<app>/r?net=3000000&dep=1&kids=0`).
- **무료로 둔다.** 서버 0원 전략에서 신규 유입 수단은 공유 카드 하나이므로 광고 뒤에 두지 않는다. 카드 하단에 앱 딥링크와 이름을 고정 노출한다.

### 3-4. 무료·광고 흐름
- **무료(항상)**: 역산·정방향 계산 무제한, 항목별 공제 내역, 협상 카드 생성·공유, 퇴직금, 연차수당, 시나리오 저장 3개.
- **게이트(리워드 광고 → 오늘 하루 열기)**: 시간축 카드, 시나리오 2개 병렬 비교, 저장 3개 초과. 광고 1회 시청으로 세 기능이 함께 열린다.
- 게이트 카드를 탭하면 바텀시트: "광고 보고 오늘 하루 열기". 사용자가 탭했을 때만 뜬다. 열림 상태는 기기 로컬 자정까지(Storage에 만료 시각 저장).
- 리워드 광고는 홈 진입 시 프리로드. 실패 시 "지금은 광고를 불러올 수 없어요. 잠시 후 다시 시도해 주세요" 후 홈 복귀.
- 배너: 홈 하단, 결과 화면 최하단(면책 문구 아래).

메인 훅(역산)은 게이트 밖에 둔다. 첫 화면에서 차별점이 체감되어야 하므로 여기에 광고를 걸면 안 된다.

| ID | 요구사항 |

| CE-9 | 연차수당 = 1일 통상임금 × 미사용 연차 일수. 1일 통상임금 = 월 통상임금 ÷ 209(주 40시간 기준, 소정근로시간 입력 가능). |

### 5-2. 파이프라인
1. 간이세액표 엑셀을 홈택스에서 수동 다운로드 → `data-src/`에 보관(원본 보존) → `npm run data:build`로 JSON 변환. 변환 시 구간 연속성(이전 행 hi = 다음 행 lo), 열 수 11, 세액 단조 비감소를 단정.
2. 요율표는 수동 편집 JSON. 각 행에 출처 URL·확인일.
3. `check:data`가 프로덕션 빌드를 게이트. 앱은 런타임에 어떤 외부 데이터도 호출하지 않는다.
4. 골든 케이스(CE-11)를 `docs/FACT_CHECK.md`에 기록. 홈택스 조회 결과 스크린샷 대신 조회 조건·결과값·조회일을 표로.

## 7. 기술 아키텍처

```
[빌드 타임]  홈택스 엑셀 ──build-tax-table.ts──▶ src/data/tax-table/*.json
             rates.json (수동)                    check-data.ts (빌드 게이트)
[앱 번들]   React + TS (Vite) + @apps-in-toss/web-framework 3.3.x
             ├─ engine/    net(), gross(), netByYear(), severance(), leavePay() — 순수 함수, vitest
             ├─ data/      세액표 JSON, 요율 JSON
             ├─ (공용) @ait/kit — platform(ads, storage, env, nav, backstack, share, anon-user), 스크립트(lint-copy, gen-logo, check-ad-ids)
             ├─ components/ 숫자 입력, 결과 카드, 막대 차트(fx-replay 차트 확장), 카드 이미지 생성
             └─ screens/   홈(역산), 정방향, 상세, 퇴직금, 연차수당, 저장·비교, 설정
[런타임]    서버 없음. 네트워크는 앱인토스 SDK(광고)만.
```

- **공용 패키지 `@ait/kit`** (확정, 2026-09-07): fx-replay의 `src/platform/*`(ads, storage, env, nav, backstack, share)과 `scripts/lint-copy.ts`·`gen-logo.ts`를 루트 `packages/ait-kit`로 추출하고, fx-replay와 net-pay가 npm workspaces로 함께 사용한다. 앱별로 달라지는 값(Storage 키 접두어, 광고 그룹 ID, 금지어 사전, 앱 이름)은 전부 파라미터로 주입한다. 설계는 [../../docs/SHARED_PACKAGE.md](../../docs/SHARED_PACKAGE.md). fx-replay 마이그레이션은 기존 테스트 82개가 그대로 통과하는 것을 완료 조건으로 한다.
- **호스팅**: 앱인토스 번들 업로드. 별도 호스팅 없음.
- **저장**: 앱인토스 Storage API, 스키마 버전 필드.
- **분석**: 앱인토스 분석 대시보드 + 커스텀 이벤트 `calc_done{mode}`, `gate_view{feature}`, `ad_reward_earned`, `share_card_created`, `scenario_saved`.
- **테스트**: 엔진 단위 테스트, 골든 케이스 20개, 데이터 검증(구간 연속성·단조성), 금지어 린트, 딥링크 파서.
