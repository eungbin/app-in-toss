## 1. 검증 방법

기대값을 구현 코드로 만들면 자기 자신을 검증하는 셈이 된다. 그래서 두 경로만 쓴다.

1. **세액**: 원문 텍스트에서 구간 경계(`이상`·`미만`)로 직접 정규식을 걸어 11개 값을 읽는다.
   파서(`scripts/hwpx.ts`·`scripts/law-byl.ts`)의 순차 파싱과 다른 경로이므로 파서 버그와 독립적이다.
   행이 한 번만 잡히는지도 단정한다. 두 시행판을 **서로 다른 형식·서로 다른 파서**로 읽어 교차 확인한다.
2. **보험료**: 고시 숫자(요율·상하한)를 테스트 안에 리터럴 산술로 다시 적어 대조한다.
3. **홈택스 조회기**: 원문과 무관한 독립 출처다. 실제 조회 결과를 테스트에 고정해
   파서·열 매핑·초과 산식·절사를 한 번에 확인한다(G 그룹). 계산기가 자바스크립트 앱이라
   curl로는 못 받지만 브라우저로는 조회가 된다.

실수령 통합 케이스(21·22번)는 위 두 재료만으로 기대값을 조립한 뒤 `computeNet` 결과와 맞춘다.

## 3. 자동 검증이 안 되는 항목

아래는 사람이 한 번 확인해야 한다. 국세청·공단의 **계산기**는 모두 자바스크립트 앱이라 서버에서 값을 받아올 수 없다
(2026-09-07 확인: 홈택스·손택스·4대사회보험 정보연계센터 모두 페이지 껍데기만 응답).
반면 **법령·고시 원문**은 국가법령정보센터에서 평문으로 받을 수 있어 자동 검증에 넣었다.

### 3-1. ~~2026-03-01 시행판 세액표~~ → 해결 (2026-09-07)

국가법령정보센터가 별표를 평문으로 내려준다는 것을 확인해 `npm run data:fetch`로 자동 수집하도록 했다.
법령 본문은 저작권 보호 대상이 아니다(저작권법 제7조 제1호).

수집 경로: 법령 페이지에서 `lsiSeq` → 별표2 링크에서 `bylSeq` → `lsBylTextDownLoad.do` POST.
공공데이터포털은 개정 반영이 늦어(2026-09-07 기준 2024-02-29 판까지만) 법령정보센터를 1순위로 쓴다.

**개정 내용은 자녀 차감액뿐이었다.** 본문 646구간과 초과 산식은 2024-02-29 판과 완전히 동일하다(골든 25번).
2026년 국민연금 요율 인상(9.0 → 9.5%)이 연금보험료공제를 거쳐 본문 세액을 바꿨을 것이라는
사전 추정은 **틀렸다**. 원문 비교로 확인했다.

### 3-2. 절사 규칙 — 소득세·지방소득세는 확인됨, 보험료는 남음

| 항목 | 전제한 규칙 | 상태 |
|---|---|---|
| 소득세 | 간이세액표 값에 선택 비율(80/100/120%)을 곱한 뒤 10원 미만 절사 | **확인됨** — 홈택스 조회 결과와 일치 (골든 28~31) |
| 지방소득세 | 소득세 × 10%, 10원 미만 절사 | **확인됨** — 홈택스 조회 결과와 일치 |
| 건강보험 상·하한 | 보수월액보험료(총액) 기준 | **확인됨** — 고시 제2·3조 원문 |
| 국민연금 | 기준소득월액을 천 원 단위로 절사한 뒤 요율 적용, 보험료는 원 미만 절사 | 미확인 |
| 건강보험 | 총액 산출 → 상·하한 → 근로자 절반 → 10원 미만 절사 | 미확인 |
| 장기요양 | 근로자 부담 건강보험료 × 13.14%, 10원 미만 절사 | 미확인 |
| 고용보험 | 과세 월급 × 0.9%, 10원 미만 절사 | 미확인 |

남은 네 항목의 **영향 범위는 항목당 10원 미만**이다. 네 개를 다 틀려도 월 실수령 오차는 40원 안쪽이고,
월 300만 원 기준 0.0013%다. 골든 20번이 현재 전제를 고정하므로 값이 바뀌면 테스트가 깨진다.

확인이 막힌 이유: 국민연금공단·건강보험공단·4대사회보험 정보연계센터 계산기는 브라우저 접근이
차단되거나(도메인 정책) 자바스크립트 앱이라 결과를 읽을 수 없었다. 법령·시행령 본문에서도
단수 처리 조항을 찾지 못했다(각 공단 내부 규정일 가능성). 사람이 공단 계산기에서 아래 표로 확인하면 된다.

### 3-3. 과거 연도 요율

`src/data/rates.json`의 `needsVerification`에 남아 있는 항목이다. 시간축 화면이 이 값을 쓰고,

### 3-4. ~~퇴직금·퇴직소득세 대조~~ → 해결, 연차수당은 남음

**홈택스 퇴직소득 세액계산(모의계산)은 쓰지 않았다.** 주민등록번호를 필수로 요구하는

사람이 홈택스 모의계산으로 한 번 더 맞춰보면 더 확실하다.

### 3-5. 상여 원천징수 — 외부 대조 불가

상여 달 소득세는 소득세법 제136조 제1항 제1호(지급대상기간이 있는 상여등)를 구현했다.
조문 원문은 국가법령정보센터에서 받아 확인했다(2026-09-07).

**접근 가능한 외부 계산기가 없다.** 홈택스 모의계산은 주민등록번호를 요구하고,
상여 원천징수만 계산해 주는 공개 계산기는 찾지 못했다. 그래서 다음을 테스트로 고정했다.
- 한 지급대상기간의 세액 합계가 `간이세액(월평균) × 기간월수`와 맞는다
- 상여를 12회로 나누면 균등 지급 계산에 수렴한다(오차 10원 이내)
- 연간 실수령이 균등 지급과 2만 원 이내로 맞는다(절사 누적분)

화면에 "회사 급여 시스템의 처리와 다를 수 있어요"를 표기한다.
사람이 급여명세서와 한 번 맞춰보면 더 확실하다.

남은 것
- **연차수당**: 공식 계산기가 따로 없다. 산식(1일 통상임금 × 미사용 일수,
  1일 통상임금 = 월 통상임금 ÷ 소정근로시간 × 8)은 근로기준법 해석대로 구현하고
  단위 테스트로 고정했다. 회사 규정에 따라 통상임금 범위가 달라진다는 안내를 화면에 넣었다.
