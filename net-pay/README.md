# net-pay — 세후로 말해줘

받고 싶은 **세후 월급으로 필요한 연봉을 역산**하는 앱인토스 미니앱. 정방향 계산(연봉 → 실수령), 퇴직금, 연차수당도 함께 제공한다.

- 기획·설계: [PRD](docs/PRD.md) → [기능 명세](docs/FUNCTIONAL_SPEC.md) → [화면 흐름](docs/SCREEN_FLOW.md)
- 공용 패키지: [`@ait/kit`](../packages/ait-kit) — [설계](../docs/SHARED_PACKAGE.md)

## 시작하기

```bash
# 의존성은 모노레포 루트에서 설치한다
(cd .. && npm install)
npm run data:build # 원본 HWPX → 번들 JSON (원본은 data-src/tax-table/ 에 들어 있다)
npm run dev        # http://localhost:5174
```

## 간이세액표 원본

원본은 소득세법 시행령 별표2를 담은 HWPX이고 라이선스는 **이용허락범위 제한 없음**이다.
표·비고·초과 산식을 전부 원본에서 읽으므로 사람이 숫자를 옮겨 적는 단계가 없다.

```bash
npm run data:fetch   # 공공데이터포털에서 최신 원본 받기 → data-src/tax-table/<시행일>.hwpx
npm run data:build   # 파싱·검증 → src/data/tax-tables.json
```

**현재 상태**: 번들에는 `2024-02-29` 시행판이 들어 있다. 공공데이터포털은 아직 이 판까지만 제공한다.
`2026-03-01` 시행판(개정 2026-02-27, 자녀 차감액 20,830 / 45,830 / 33,330원)은 홈택스에서 받아야 하고,
그때까지 `check:data`가 프로덕션 빌드를 막는다.

1. 홈택스 > 세금신고 > 원천세 신고 > **근로소득 간이세액표**에서 조견표를 받는다.
2. `data-src/tax-table/2026-03-01.hwpx`로 저장한다. **파일명이 시행일**이다.
3. `npm run data:build` → `npm run check:data`

HWPX가 아닌 형식(엑셀·PDF)만 있으면 파서를 손봐야 한다. HWPX 파싱은 `scripts/hwpx.ts`, ZIP 해제는 `scripts/zip.ts`(의존성 없이 Node zlib만 사용).

## 스크립트

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 (5174) |
| `npm run check` | 타입체크 + 문구 린트 + 테스트 |
| `npm run data:fetch` | 공공데이터포털에서 세액표 원본(HWPX) 받기 |
| `npm run data:build` | 원본 HWPX → 번들 JSON (표·비고·초과 산식 파싱 + 검증) |
| `npm run check:data` | 최신 시행판 누락·미확인 요율·손으로 만든 표 차단 |
| `npm run build` | check + check:data + vite build + ait build |

## 알아 둘 것

- **정방향은 단조 증가가 아니다.** 가장 큰 계단은 과세 월급이 표 상한(1,000만 원)을 넘는 지점이다. 별표2가 상한 기준 세액에 25,000원을 더하기 때문에 연봉 122,400,012원에서 실수령이 **월 27,499원** 떨어진다. 역산은 연봉 120만 원 격자(이 위에서는 단조)로 탐색한 뒤 칸 안을 훑고, 화면에 내보내는 만 원 단위 연봉에서도 목표가 지켜지는지 따로 확인한다. 기능 명세 3-4절.
- **저소득 구간에는 계단이 있다.** 과세 소득이 생기는 순간 보험료 하한이 걸려 실수령이 한 번 떨어진다. 제도상 동작이며 테스트로 고정돼 있다.
- 모든 계산은 기기 안에서 끝난다. 서버가 없고 입력값을 어디로도 보내지 않는다.
